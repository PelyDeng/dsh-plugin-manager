# DSH Plugin Manager v0.20.0

本版把官方宿主从 `0.1.6-alpha.1` 升级到 `0.1.6-alpha.2`，管理器的启动诊断解析兼容新旧两代官方格式，`version check` 新增宿主锚点核验，宿主升级漏改任何锚点都会在检查时报出。

公共 manager、kit、auth、example 统一为 `0.20.0`；子模块锁定 `ddefc45fbc7f8e46dd73185e68295696d1297887`，对应官方标签 `dsh-v0.1.6-alpha.2`。

## 宿主升级与兼容

- 官方新版把必需条目失败的启动诊断重写为分组格式：`startup failed: N required plugins did not activate` 抬头，其下 `Failed plugins`（含每个插件的 `Package:` 与原因）与 `Plugins waiting for services` 两组，可选条目并入同一份诊断；完整诊断同时写入 `$DSH_HOME/logs/startup-<时间戳>-<id>.log`。可选条目警告仍是 `warning: N entries did not activate`。管理器同时接受两代格式：托管插件未激活的判定不受影响；必需条目失败时整块官方诊断原样转报，托管插件混在分组里也能比对出来，两份证据都在最终错误里。
- 官方新版把普通 Node 启动的默认包解析代由 link 改为 runtime：不再在 profile 的 `node_modules` 下物化回退符号链接，插件就位以 profile manifest（`dsh.profile.bundles`）为准。框架的源码与固定镜像两种基底都从源码检出启动，插件按包名解析的行为不变。
- 官方新版重写了 `dsh plugin` 子命令并删除了 `dsh.profile.patchReload` 配置键。管理器经该子命令转发 pnpm，参数面保持；git 托管插件的构建脚本需要在 profile 的 `pnpm-workspace.yaml` `allowBuilds` 显式放行。
- Session 仍是 V3，官方两版之间没有新的格式迁移；`dsh-host-webserver`、`dsh-tools`、`dsh-user-approval`、`dsh-ptc-runtime`、`dsh-attachment`、cordis 的源码无实质变化。39 个宿主内部包全部随新版重发，锁文件与发布年龄排除表已同步（排除表按精确版本并集并列新旧两版）。

## 宿主锚点核验

- `node scripts/version.mjs check` 现在以 `deepseek-harness/package.json` 为宿主侧唯一事实源，核验根 `pnpm-workspace.yaml` 的发布年龄排除、`doc/host-compatibility.md` 的版本与 gitlink 提交、`tools/builtin-build/input.json` 的 frameworkVersion 与框架版本的一致性；发行包检出没有子模块时宿主核验自动跳过。历史上升级宿主漏改过这些锚点，此后漏改直接让检查失败。

## 安装与升级

本次附件包含 manager、kit、公共应用、精简部署包、独立起步包和 SHA256SUMS.txt。核对摘要后按[首次部署指南](https://github.com/PelyDeng/dsh-plugin-manager/blob/v0.20.0/doc/first-deployment.md)操作。

升级公开框架文件时保留 `incoming/` 与 `.local/`。源码部署按新 gitlink 收敛并重建宿主；使用固定宿主镜像的站点先构建新版镜像并核验其摘要，再更新站点引用。业务插件保留各自的宿主版本声明与原有发布目录，本版不重建作者源码；业务插件自身升级到 `0.1.6-alpha.2` 时再对齐依赖。
