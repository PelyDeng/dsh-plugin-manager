# DSH Plugin Manager v0.16.0

本版增加插件产物一键部署。外部作者在独立项目中使用已有 `pack` 命令交付完整发布目录，部署者将目录放入站点 `incoming/`，执行 `build.ps1` 或 `build.sh` 即可安装和更新。

## 部署与交付

- 增加精简部署包和独立项目起步包。部署包携带管理工具、固定运行镜像信息与可选认证插件，不需要作者源码或框架工作区。
- 自动检查所有直接发布目录、插件 ID、包名和归档摘要。保留插件需要保留对应产物；缺包不会自动视作停用，也不会自动挑选版本。
- 源码部署继续使用 `source`；精简部署包默认 `archives`。两条路径共用站点操作、锁、输入快照和恢复规则。按需源码重建继续使用 `--rebuild-plugins`。
- 新部署记录冻结原工具树、插件归档和私有配置。`--resume` 继续原输入；同包业务配置修正使用 `--recover --data-compatible`。更换修复包的高层恢复本版不提供。
- 旧实例配置和持久数据继续沿用原位置；旧记录保留兼容入口。无法核实进程或数据归属时保留现场，不自动删除锁和数据。

## 作者接入与文档

- 起步包提供最小公开接口与统一鉴权两个独立项目，说明配置、打包、首次登录、授权和正常更新步骤。
- 部署说明按主题维护唯一正文，随包文档及开发者助手的离线指南从固定片段同步生成。
- 管理工具准备步骤复用同一实现；独立示例读取自身包信息；示例前后端复用翻译判定规则。CI 删除 `check` 前重复的构建步骤。

## 升级注意

原站点更新框架公开文件时保留 `incoming/` 和 `.local/`。未完成操作继续使用记录中的原工具与输入，不要用覆盖配置、删除状态或删除数据的方式强行重建。

部署包的运行镜像按平台提供，并使用不可变摘要。无匹配平台镜像时会明确拒绝部署；容器健康不代替应用登录、授权和实际业务请求验收。
