# DSH Plugin Manager v0.21.0

本版把官方宿主从 `0.1.6-alpha.2` 升级到 `0.1.7-alpha.2`（区间 1460 提交）。官方这一版有两处健康判定语义的变化：bundle 层失败从「启动失败」改为「跳过继续启动」，工具结果提升为一等 tool-role 消息并随 Session V4 落盘。管理器相应重构了启动诊断解析（世代描述表驱动，并新增被跳过 bundle 的健康判定），会话快照工具扩展了 V4 codec。

公共 manager、kit、auth、example 统一为 `0.21.0`；子模块锁定 `00102833dfaee1da9f48a3a8eae9d34005a75218`，对应官方标签 `dsh-v0.1.7-alpha.2`。

## 宿主升级与兼容

- 官方 `0.1.7` 起 bundle 层失败不再中止启动：解析、manifest 或 patch 加载失败的 bundle 会被宿主写一行 `dsh: skipping profile bundle "<包名>": <错误>` 后跳过该层继续启动（profile manifest 与用户 patch 的错误仍属致命）。「宿主启动成功」不再等于「站点插件全部就位」。管理器解析该行并把命中托管名单的被跳过 bundle 按启动失败处理，证据与未激活条目、官方必需失败块合并报出。启动诊断本身的两代格式（`0.1.6-alpha.1/alpha.2`）未再变化，解析锚点原样有效。
- Session 格式为 V4：旧会话读取时官方持久化层先迁移，首次写入发布 V4 generation，原始文件保持不变。**回滚不兼容**——V3 读取器拒绝 V4 generation，升级后产生的会话数据不能被 `0.1.6` 宿主读取；升级前必须停写并备份持久数据目录，回退需要从升级前备份恢复。批量把既有会话发布为 V4 可用官方一次性命令（宿主仓库内 `pnpm run migrate:sessions-to-v4`，不用模型）。V3→V4 把工具结果提升为一等 tool-role 消息并要求显式子会话证据；管理器的 `restoreSessionSnapshot`/`mergeLegacyFeedback` 已扩展 V4 codec，离线快照用 `createSessionFormatCatalogWithChildren([])` 声明无子。
- 官方 `0.1.7` 起 `deepseek-official` 为 Messages-only：Chat Completions 实现与协议选择键删除，Anthropic 风格 Messages 是唯一通路。example 的真宿主模型替身收敛为只接受 `/messages` 请求，协议漂移显式报错。
- 包解析代（link/dual/runtime）被彻底移除，只剩运行时解析；启动时自动清理 link 时代的 `.dsh-module-fallback` 投影。`@deepseek-ai/dsh-agent-presets` 拆为 `dsh-agent-preset` 与 `dsh-agent-preset-registry`；`dsh-agent-default-model` 的配置字段 Volatile 化（服务签名不变）。框架对这些面的 API 零引用，行为无需适配；细节见[宿主兼容说明](https://github.com/PelyDeng/dsh-plugin-manager/blob/v0.21.0/doc/host-compatibility.md)。
- vendor 内部包重发：cordis 4.0.4、schemastery 3.18.4、cosmokit 1.8.5 等（仅新增 volatile 能力，向后兼容）。锁文件与发布年龄排除表已同步，排除表按精确版本并集并列新旧两版，并新增 `dsh-session-format-v3-to-v4`。

## 启动诊断解析的世代描述表

管理器把两代官方诊断的抬头与明细行形状收敛为世代描述表：每代是一组具名锚点（含 severity），新增世代只加表项不改控制流。0.1.7 未改诊断格式，两代表项与 alpha.2 逐字一致；既有诊断用例（含失败原因里夹带诱饵行的真实宿主用例）原样保留作为等价迁移护栏。被跳过 bundle 的锚点与官方 `profile.ts` 的输出逐字对齐（stderr 裸行、`JSON.stringify` 包名）。

## 安装与升级

本次附件包含 manager、kit、公共应用、精简部署包、独立起步包和 SHA256SUMS.txt。核对摘要后按[首次部署指南](https://github.com/PelyDeng/dsh-plugin-manager/blob/v0.21.0/doc/first-deployment.md)操作。

升级公开框架文件时保留 `incoming/` 与 `.local/`。源码部署按新 gitlink 收敛并重建宿主（构建面用 `build:lib:host`、`build:lib:client` 与 `build:web`）；使用固定宿主镜像的站点先构建新版镜像并核验其摘要，再更新站点引用。业务插件保留各自的宿主版本声明与原有发布目录，本版不重建作者源码；业务插件自身升级到 `0.1.7-alpha.2` 时再对齐依赖。
