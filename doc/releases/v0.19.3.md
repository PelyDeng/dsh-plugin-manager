# DSH Plugin Manager v0.19.3

> 本版推了标签但没有发布附件：Release 工作流的 `deployment-smoke` 在「核验容器挂载与权限」失败——作业把容器用户写死成 1000，而 GitHub runner 是 `1001:1001`，本版只是删掉那两行、默认值仍是 1000，所以照旧被拒。修正见 [v0.19.4](v0.19.4.md)，请直接使用 0.19.4。

本版的产品修复与 0.19.2 完全相同：精简部署包（archives 入口）先在公开构建视图内装依赖再用视图入口构建、worker 结束回报退出码。差别只在 Release 工作流自身——0.19.2 因此只推了标签、没有发布附件。宿主仍是 `0.1.6-alpha.1`（提交 `0a15e36e7f82b6ed45af6fa9759f29b40dcd965d`），manager、kit、auth、example 统一为 `0.19.3`。

## 修复：Release 的端到端部署作业

- 站点私有配置必须是 `0600`（`readPrivateConfig` 拒绝任何组/其他权限位），而作业用重定向直接写 `.local/env.conf`，按默认 `umask 022` 得到 `0644`，于是部署步骤在几秒内以「私有配置权限必须为 0600。」失败。现在整个步骤 `umask 077`，写完再 `chmod 600` 一次。
- 作业过去写死 `DSH_CONTAINER_UID=1000` / `DSH_CONTAINER_GID=1000`。新站点在 Linux 上本来就按当前非 root 用户初始化这两个值；写死会在宿主属主不是 1000 的机器上让容器用户拿不到绑定目录权限（「核验容器挂载与权限」直接拒绝）。现在交给平台默认。
- 这两条是工作流现场问题，不是产品缺陷：手工部署按[首次部署指南](https://github.com/PelyDeng/dsh-plugin-manager/blob/v0.19.3/doc/first-deployment.md)创建 `.local/` 时由管理器自己写入私有配置，权限正确。

## 为什么没有随 v0.19.2 发布

0.19.2 推了标签后，`runtime` 与 `build` 成功，`deployment-smoke` 在部署步骤失败，`publish` 被跳过，因此没有 GitHub Release。定位没有额外成本：0.19.2 新增的失败诊断把 `build.log` 末尾转成 `::error::` 注解，「私有配置权限必须为 0600。」直接出现在注解区。

## 安装与升级

本次附件包含 manager、kit、公共 auth/example 应用包、精简部署包、独立起步包和 SHA256SUMS.txt。核对摘要后按[首次部署指南](https://github.com/PelyDeng/dsh-plugin-manager/blob/v0.19.3/doc/first-deployment.md)操作。

- 精简部署包：首次 build 会在公开构建视图里安装框架工作区依赖，并按站点根清单准备固定版本的 pnpm，这一步需要网络或完整缓存；旧部署包解压覆盖公开脚本、`tools/`、`source/`、`framework-runtime.json` 与公开模板即可，`incoming/`、`.local/` 原样保留。
- 源码站点：普通 `build.sh` / `build.ps1` 从当前现场收敛即可，本版不改数据与配置。
- 固定镜像站点：镜像无需更换，本版只改部署包与脚本行为。
