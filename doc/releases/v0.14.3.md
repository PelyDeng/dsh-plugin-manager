# DSH Plugin Manager 0.14.3

这次发布整理了项目文档和 example 随包知识：先说明用途和操作，再解释必要术语，拆开过长段落，并修正配置字段及源码锁恢复说明。开发约定也已明确：平时在本地开发，按改动选择检查；用户要求发版后，再统一确定版本和更新服务器。

同时修正了一处测试环境问题：临时 Git 仓库不再启动后台维护，避免测试结束清理目录时仍有 Git 进程写入。正式仓库的 Git 配置和部署逻辑不受影响。

相对上一个公共 Release 0.13.2，本次还包含 0.14 系列已提交的更新：

- auth 管理页可选择新会话的默认模型；旧会话和分支沿用历史记录中的模型。
- example 按初学者需要解释问题，并能检索随包公共源码，引用文件和行号。
- kit 提供独立的 `models` 导入入口，仅使用模型接口时无需安装工具类型依赖。
- 源码部署增加 `doctor` 和 `unlock-source`，先确认进程退出，再备份并解除遗留源码锁。

manager、kit、auth、example 统一为 0.14.3。安装方式见[上手指南](../getting-started.md)，源码部署见[首次部署](../first-deployment.md)。Release 附件包括 manager 和 kit 的 tgz、公共 auth/example 应用 ZIP，以及 `SHA256SUMS.txt`。宿主保持 gitlink `d347e703908d0406b7a7ef80e3a0e594d86b2215`，归档不包含宿主源码、凭据或运行数据。

文档经过独立的规范与需求评审。本地构建、文档链接、模板同步、版本测试 4 项、example 测试 76 项及独立安装包验证已通过。源码启动测试在 Windows 上通过 5 项、跳过 1 项既有 POSIX 场景，在 Linux 隔离容器中通过 6 项。

发布提交还需通过 GitHub 的 Linux、Windows、macOS 与 Node.js 22、24 六组检查；Release 工作流会重新构建、测试并验证独立安装包。检查记录以此标签对应的 Actions 运行结果为准，不代表已经完成真实模型或浏览器全流程验收。
