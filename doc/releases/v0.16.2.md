# DSH Plugin Manager v0.16.2

本版补齐部署前的框架版本对照。升级时显示可核验的旧版本和目标版本；新发布配置保存框架版本，之前的 schema 3 成功记录在确认与当前部署身份一致后补充旧版本。无法确认的历史记录仍明确显示未知，不推测版本。

公共 manager、kit、auth、example 统一为 `0.16.2`。插件产物部署、独立作者起步包、同包配置恢复和首句自动标题继续包含在本版：

- 作者在独立项目中使用 `pack` 交付完整发布目录。部署者将 manifest.json 及全部引用归档放入 `incoming/` 的直接子目录，再执行框架 `build.ps1` 或 `build.sh`；部署机器不需要作者源码或框架检出。
- 精简部署包默认 `archives`，源码入口默认 `source`。输入发现、配置、锁和恢复共用实现，源码仍支持 `--rebuild-plugins`。incoming 是完整集合，缺包不表示停用，不自动选择版本。
- `--resume` 使用原工具与冻结输入；同包业务配置修正使用 `--recover --data-compatible`。更换修复包的高层恢复继续延期，不删除锁或修改状态绕过校验。
- 可选认证目录正确保留 auth 自身的构建与验证记录。两个独立起步项目覆盖公开接口与统一鉴权，部署文档说明首次改密、授权及更新步骤。
- kit 的 `registerConversationTitles` 复用官方首句标题能力。example 接收延迟到达的自动标题，保留手动改名；随包 FAQ 与问答源码快照同步当前部署、配置、恢复与会话说明。授权后无需模型也可阅读 FAQ。

## 安装与升级

本次附件包含 manager、kit、公共应用、精简部署、独立起步包和 SHA256SUMS.txt。核对摘要后按[首次部署指南](https://github.com/PelyDeng/dsh-plugin-manager/blob/v0.16.2/doc/first-deployment.md)操作；部署包和起步包也附有离线正文。

升级公开框架文件时保留 `incoming/` 和 `.local/`。原配置、账号和业务数据不自动迁移；optional/auth 更新不会自动替换 incoming 中的认证包。升级前停写并备份，未完成操作使用其原发布记录恢复。

从 0.15 系列升级时，example 历史索引会升至 schema 4；旧代码不能直接读取新版索引，回退需使用升级前一致备份并保留升级后数据。从 0.16.0 或 0.16.1 升级不增加新的历史库迁移。

运行镜像固定为该版经匿名拉取验证的 Linux amd64 摘要，其他架构需有实际验证的匹配镜像。官方宿主保持 `0.1.5-alpha.2`、提交 `b2e3b2a0125854567a4a5fcba75782e42fe84901`。

发行工作流执行检查、行为测试、独立安装包验证和附件摘要校验，实际结果见 [GitHub Actions](https://github.com/PelyDeng/dsh-plugin-manager/actions)。自动检查、容器健康、实际登录与业务请求、浏览器视觉验收分别记录，不互相替代。
