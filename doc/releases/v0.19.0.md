# DSH Plugin Manager v0.19.0

本版把官方宿主从 `0.1.5-alpha.2` 升级到 `0.1.6-alpha.1`，按新版启动语义加固了受管插件的激活判定，并新增构建逐步耗时记录，方便定位部署到底慢在哪一步。

公共 manager、kit、auth、example 统一为 `0.19.0`；子模块锁定 `0a15e36e7f82b6ed45af6fa9759f29b40dcd965d`，对应官方标签 `dsh-v0.1.6-alpha.1`。

## 宿主升级与兼容

- 官方新版改变了启动失败的判定：只有全局必需条目（`agent-loop`、`webserver`、`modules`、`connection`、`headless-runner`、`acp`、`sdk-jsonrpc-server`）失败会中止启动并非零退出；其余条目导入失败、配置校验失败或一直等待依赖，只打印一条 `warning: N entries did not activate` 警告，进程继续服务。端口可访问不再等于站点可用，所以 build 与 start 现在读这条诊断：受管插件未激活直接按启动失败处理并报出插件名与原因，必需条目失败则把官方诊断一并报出。
- 官方删除了 `@deepseek-ai/dsh-code-runtime`（能力族改为 `dsh-ptc-runtime`），`workflow-worker-thread` 更名为 `workflow-ptc`。框架的依赖声明、锁文件与 `pnpm-workspace.yaml` 的发布年龄排除表已同步；业务插件用到的官方子路径（`dsh-llm/assistant-stream`、`dsh-llm/brand`、`dsh-session/surface`、`dsh-token-meter/client` 等）在新版仍然导出。
- 旧反馈迁移脚本不再写死宿主版本：它按运行镜像根清单核对每个官方包的版本，升级宿主不必改脚本，也不会放过混装。
- 源码检出启动仍走 link 模式的模块回退，插件按包名解析的行为与旧版一致；宿主新增的 `$DSH_HOME/cache/` 是可丢弃缓存，备份与迁移不需要它。
- Session 仍是 V3，日志不需要再次迁移。固定宿主镜像必须按新版本重建，不能沿用旧宿主的镜像摘要。

## 构建耗时记录

- 每次源码构建都把逐步耗时写成 `timings.json`（位于本次构建的私有日志目录，权限 0600，原子写入）：阶段 id、标签、起止时间、耗时、状态，加上总墙钟、阶段耗时之和、重叠时间与运行环境（框架版本、输入形态、Node、平台、架构、包管理器）。
- 成功和失败都写：失败时未结束的阶段标成 `unfinished`，慢步骤和卡住的位置一眼可见。终端在阶段汇总前打印这份记录的路径。
- 发布记录登记这份路径，`check-records` 只读读出最慢的几个阶段；记录缺失或路径越界都不报错、不写文件。

## 安装与升级

本次附件包含 manager、kit、公共应用、精简部署包、独立起步包和 SHA256SUMS.txt。核对摘要后按[首次部署指南](https://github.com/PelyDeng/dsh-plugin-manager/blob/v0.19.0/doc/first-deployment.md)操作。

升级公开框架文件时保留 `incoming/` 与 `.local/`。源码部署按新 gitlink 收敛并重建宿主；使用固定宿主镜像的站点先构建新版镜像并核验其摘要，再更新站点引用。业务插件保留各自的宿主版本声明与原有发布目录，本版不重建作者源码；业务插件自身升级到 `0.1.6-alpha.1` 时再对齐依赖。
