# DSH Plugin Manager v0.16.1

本版交付插件产物一键部署、独立作者起步包和首句自动标题，并修正从多插件发布清单提取可选认证包时的构建记录归属校验。公共 manager、kit、auth、example 统一为 `0.16.1`。

## 部署与作者接入

外部作者在独立项目中沿用 `pack`，交付包含 manifest.json 和全部引用归档的完整目录。部署者将其放入 `incoming/`，执行部署包里的 `build.ps1` 或 `build.sh`。部署机器不需要作者源码或框架工作区。

- 精简部署包包含管理工具、固定运行镜像信息、离线操作说明和按需使用的认证插件。独立起步包提供公开接口与统一鉴权两个项目。
- 产物部署默认 `archives`，源码部署继续默认 `source`。二者共用站点配置、锁、输入快照和恢复实现；源码按需重建仍使用 `--rebuild-plugins`。
- incoming 是完整部署集合。缺包不表示停用；重复 ID、包名、摘要错误和越界路径会在停服前拒绝，不自动选择版本。
- `--resume` 使用原工具和冻结输入；同包业务配置修正使用 `--recover --data-compatible`。更换修复包的高层恢复继续延期。
- 可选 auth 从组合清单中提取时，仅保留属于 auth 的构建与验证记录，避免其他插件的记录阻断部署包生成。

首次部署、更新和排错步骤见[产物一键部署](https://github.com/PelyDeng/dsh-plugin-manager/blob/v0.16.1/doc/first-deployment.md)。已有 Node 项目需满足插件入口和打包契约；非 Node 服务继续独立部署，由插件调用其接口。

## 对话与文档

kit 提供 `registerConversationTitles`，订阅官方宿主的首句标题提炼。example 接收回答结束后到达的标题并有界刷新，不重复发起标题模型请求。自动标题不能覆盖手动改名或升级前的标题，可信用户的再次改名仍可更新。

部署与开发资料按主题维护唯一正文，随包指南和 example FAQ 从固定片段同步生成。example 的问答知识和源码快照包含当前产物部署、源码入口、恢复边界、鉴权、配置与自动标题；没有模型时仍可在授权后直接阅读指南。

## 升级与验证

升级框架公开文件时保留 `incoming/` 和 `.local/`，已有配置与持久数据不自动迁移。可选 auth 不会自动替换 incoming 中的旧认证插件。未完成操作按原发布记录恢复，不删除锁或修改状态绕过检查。

example 历史索引升级至 schema 4。升级前停写并备份历史索引、官方会话及私有配置；旧代码不能直接读取新版索引，回退需使用升级前一致备份并保留升级后数据。

附件包含 manager、kit、公共 auth/example 应用包、精简部署包、独立起步包及 SHA256SUMS.txt。部署包使用经过匿名拉取核验的固定 Linux amd64 运行镜像；其他架构需有该版本实际验证的匹配镜像。官方宿主保持 `0.1.5-alpha.2`、提交 `b2e3b2a0125854567a4a5fcba75782e42fe84901`。

工作流对发行标签执行检查、行为测试、独立安装包验证及附件摘要校验，实际状态见 [GitHub Actions](https://github.com/PelyDeng/dsh-plugin-manager/actions)。这些检查与容器健康不能代替应用登录、授权、实际业务请求或浏览器视觉验收。
