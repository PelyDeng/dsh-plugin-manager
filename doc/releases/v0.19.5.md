# DSH Plugin Manager v0.19.5

本版的产品修复与 0.19.2 起的三版相同（archives 入口在公开构建视图内装依赖、worker 回报结束消息、重复 id 在停旧前失败）。差别只在发布工作流核对**发布记录**的方式。宿主仍是 `0.1.6-alpha.1`（提交 `0a15e36e7f82b6ed45af6fa9759f29b40dcd965d`），manager、kit、auth、example 统一为 `0.19.5`。

## 修复：端到端部署作业读错了发布记录

- 作业用「`.local/artifacts` 下修改时间最新的 `source-release-*` 目录」拼出 `result.json`，但站点构建会在 `.local/artifacts` 下同时留下**准备阶段**的目录；按时间取最新会读到不是本次结果的那一份，于是断言失败、`publish` 被跳过——0.19.4 就是这样只打了标签。
- 现在改为读构建自己打印的 `发布记录：<路径>`（与计时记录同一种取法），并在缺失时把日志末尾转成 `::error::` 注解。
- 修复前先在临时分支 `ci/smoke-debug` 上用与发布工作流**完全相同**的步骤（打包 ZIP → 解压 → `bash build.sh` → 探针 → 重复 id 反例）预演通过：构建成功、记录 `status=ready` 且带计时指针、`/auth/health` 与 `/example/ready` 200、容器 `Up (healthy)`、`wallMs=31303`、25 个阶段、重复 id 在停旧前被拒绝且原容器仍在运行。通过之后才打本版标签。

## 为什么没有随 v0.19.4 发布

0.19.4 的 `runtime`、`build` 成功，`deployment-smoke` 在部署步骤失败、`publish` 被跳过，因此没有 GitHub Release。

## 安装与升级

本次附件包含 manager、kit、公共 auth/example 应用包、精简部署包、独立起步包和 SHA256SUMS.txt。核对摘要后按[首次部署指南](https://github.com/PelyDeng/dsh-plugin-manager/blob/v0.19.5/doc/first-deployment.md)操作。

- 精简部署包：首次 build 会在公开构建视图里安装框架工作区依赖，并按站点根清单准备固定版本的 pnpm，这一步需要网络或完整缓存；旧部署包解压覆盖公开脚本、`tools/`、`source/`、`framework-runtime.json` 与公开模板即可，`incoming/`、`.local/` 原样保留。
- 非 root 部署：手工创建 `.local/env.conf` 时把 `DSH_CONTAINER_UID` / `DSH_CONTAINER_GID` 写成创建站点目录的用户（管理器自动创建配置时会按平台默认填好；写死 1000 会在宿主属主不是 1000 时被权限核验拒绝）。
- 源码站点：普通 `build.sh` / `build.ps1` 从当前现场收敛即可，本版不改数据与配置。
- 固定镜像站点：镜像无需更换，本版只改部署包与脚本行为。
