# DSH Plugin Manager v0.19.4

本版的产品修复与 0.19.2、0.19.3 相同（archives 入口在公开构建视图内装依赖、worker 回报结束消息、重复 id 在停旧前失败），差别只在发布工作流里容器用户的取值。宿主仍是 `0.1.6-alpha.1`（提交 `0a15e36e7f82b6ed45af6fa9759f29b40dcd965d`），manager、kit、auth、example 统一为 `0.19.4`。

## 修复：端到端部署作业的容器用户

- 作业原先写死 `DSH_CONTAINER_UID=1000` / `DSH_CONTAINER_GID=1000`，而 GitHub 托管 runner 的用户是 `1001:1001`：绑定目录由 runner 创建，容器却以 1000 运行，于是「核验容器挂载与权限」按设计拒绝——`容器用户 1000:1000 无法访问 <站点>/.local/data；请先调整该路径权限。`（这条规矩本身是对的：非 root 部署必须让容器用户能读写绑定目录。）
- 0.19.3 只是删掉这两行，配置默认值仍是 1000，所以照旧失败。现在取 `id -u` / `id -g`，与真实非 root 部署一致——谁创建站点目录，容器就用谁的身份。
- 修复先在临时分支上的诊断工作流里验证：整条 archives 部署在 CI 上跑通——构建成功、`/auth/health` 200、`/example/ready` 200、容器 `Up (healthy)`、`wallMs=31463`、25 个阶段。通过之后才打本版标签。

## 为什么没有随 v0.19.3 发布

0.19.3 的 `runtime` 与 `build` 作业成功，`deployment-smoke` 在「核验容器挂载与权限」失败，`publish` 被跳过，因此没有 GitHub Release。

## 安装与升级

本次附件包含 manager、kit、公共 auth/example 应用包、精简部署包、独立起步包和 SHA256SUMS.txt。核对摘要后按[首次部署指南](https://github.com/PelyDeng/dsh-plugin-manager/blob/v0.19.4/doc/first-deployment.md)操作。

- 精简部署包：首次 build 会在公开构建视图里安装框架工作区依赖，并按站点根清单准备固定版本的 pnpm，这一步需要网络或完整缓存；旧部署包解压覆盖公开脚本、`tools/`、`source/`、`framework-runtime.json` 与公开模板即可，`incoming/`、`.local/` 原样保留。
- 非 root 部署：手工创建 `.local/env.conf` 时要写 `DSH_CONTAINER_UID` / `DSH_CONTAINER_GID` 为创建站点目录的用户（管理器自动创建配置时会按平台默认填好；写死 1000 会在宿主属主不是 1000 时被权限核验拒绝）。
- 源码站点：普通 `build.sh` / `build.ps1` 从当前现场收敛即可，本版不改数据与配置。
- 固定镜像站点：镜像无需更换，本版只改部署包与脚本行为。
