# DSH Plugin Manager v0.19.2

> 本版推了标签但没有发布附件：Release 工作流的 `deployment-smoke` 作业在部署步骤失败——作业自己写的 `.local/env.conf` 权限是 `0644`，而站点私有配置必须是 `0600`。产品修复本身可用，附件改由 [v0.19.3](v0.19.3.md) 交付，请直接使用 0.19.3。

本版补上 v0.19.1 漏掉的一步：精简部署包（archives 入口）的内置构建要先把依赖装进**公开构建视图**，再用视图里的入口脚本构建。v0.19.1 只打了标签、没有发布附件，其部署 ZIP 不可用，请直接用本版。宿主仍是 `0.1.6-alpha.1`（提交 `0a15e36e7f82b6ed45af6fa9759f29b40dcd965d`），manager、kit、auth、example 统一为 `0.19.2`。

## 修复：archives 入口的内置构建

- v0.19.1 把构建 worker 换成随包管理器后，`bash build.sh` 能走到准备输入阶段，但内置构建会在一两秒内退出：`Cannot find package '@dsh-plugin-manager/plugin-kit' imported from <站点>/source/packages/plugin-manager/src/plugins.mjs`。
- 原因是公开构建视图（`.local/artifacts/source-release-*/build-view`）只是公开材料的复制树，依赖要装进视图才有 `node_modules`；而入口脚本 `scripts/package-plugins.mjs` 在**加载时**就静态导入 `packages/plugin-manager/src/plugins.mjs`，它需要视图内已链接好的 kit。过去把安装留给入口脚本自己执行，脚本却连加载都过不去，于是永远走不到安装那一步。
- 现在在运行入口脚本之前显式执行 `pnpm install --frozen-lockfile`（新阶段「安装项目依赖」，与源码入口同名同实现），入口脚本也改取视图内那一份：`source/` 只作材料目录，装了依赖的视图才是本次构建的工作区。视图内安装、站点目录不安装的边界不变。
- 新增回归用例：安装必须早于入口脚本、装在视图里、入口脚本来自视图；顺序反了会在加载期直接失败。

## 修复：archives worker 会回报「构建结束」，源码锁不再被留下

- source 入口的 `deploy/scripts/build.mjs` 一直会向协调器回一条 `source-build-finished`；协调器只有在收到它、且上报的退出码与 worker 退出码一致时才释放 `.local/source-release.node.lock`。0.19.1 新增的 archives worker 没有回这条消息，于是**每次** archives 构建（成功也一样）都会留下源码锁，下一次 `build.sh` / `build.ps1` 直接被拒绝，只能先 `doctor` / `unlock-source`。
- 现在随包管理器的 worker 在结束（含失败与参数错误）时都回报退出码，两种入口的收尾行为一致。
- 新增回归用例：用真实 CLI 拉起 worker，断言结束消息的退出码与进程退出码一致。
- Release 工作流的 `deployment-smoke` 失败时会把 `build.log` 末尾若干行转成 `::error::` 注解，并先打印 node、pnpm、bash、docker 版本，下次不必再从「exit code 1」反推。

## 为什么没有随 v0.19.1 发布

v0.19.1 推了标签，但发布工作流在新增的 `deployment-smoke` 作业上失败，`publish` 被跳过，因此没有 GitHub Release，也没有任何附件发出。这条作业第一次运行就抓到了上面这个缺陷——它正是为「打包过、却从没部署过」这个盲区加的。

## 安装与升级

本次附件包含 manager、kit、公共 auth/example 应用包、精简部署包、独立起步包和 SHA256SUMS.txt。核对摘要后按[首次部署指南](https://github.com/PelyDeng/dsh-plugin-manager/blob/v0.19.2/doc/first-deployment.md)操作。

- 精简部署包：首次 build 会在公开构建视图里安装框架工作区依赖，并按站点根清单准备固定版本的 pnpm，这一步需要网络或完整缓存；旧部署包解压覆盖公开脚本、`tools/`、`source/`、`framework-runtime.json` 与公开模板即可，`incoming/`、`.local/` 原样保留。
- 源码站点：普通 `build.sh` / `build.ps1` 从当前现场收敛即可，本版不改数据与配置。
- 固定镜像站点：镜像无需更换，本版只改部署包与脚本行为。
