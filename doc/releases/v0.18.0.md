# DSH Plugin Manager v0.18.0

本版把部署收敛为**单一产物路径**，并删除中断恢复分支：内置插件固定全量构建，外部插件由作者交付完整发布目录，两类产物合并成一份安装计划；内置构建只发生在只含公开输入、带匹配锁文件的隔离视图里。失败后不再续跑，直接从当前现场重新收敛。

公共 manager、kit、auth、example 统一为 `0.18.0`。上一轮的 `0.17.0` 未单独发布，本版同时包含那批改动。

## 部署与构建

- 单一部署路径：内置自动构建加 incoming 外部产物；`--plugins` 只决定运行选集，不影响准备阶段的候选集合。缺包不表示停用、不自动挑选版本、不构建作者源码。
- 公开构建视图：收录公开目录与公开根文件（含 example 源码索引读取的 `env.conf`、`test-report.sh`），根清单、workspace 定义与锁**逐字节**取自交付的公开构建元数据，并核对同目录的 `input.json` 记录（框架版本、来源提交、三个文件的 LF 摘要）。材料缺失、版本不符、含私有 workspace 痕迹、交付物与记录不一致都直接失败；依赖只装在视图内，站点源码树不被安装。
- 发行包自带公开源码材料与公开构建输入，站点不需要框架检出；含 `plugins/external` 的检出没有交付材料时明确失败，不现场生成或裁剪元数据。
- 检查分成三条独立命令：`check`（先 build 再跑类型检查等）、`verify-package`（归档与本次构建源码字节一致）、`verify-release`（整个交付目录的清单、摘要、包结构与元数据合规）。pack 不再顺带做检查，也不宣称「已验证」。
- 归档核验按内容摘要复用：同一次发布里同样的字节只解包一次，命中返回副本，字节变了必须重解。
- 源码发布记录会报告镜像层数与存储驱动，只做报告、不做阈值判断。

## 站点绑定与一次性迁移

- 站点身份固定为 `site-binding.json` 与各持久目录下的 `.dsh-site-id` 标记：路径变化、标记缺失或标记属于别的站点，都在任何写入之前失败，不自动改写绑定。
- 旧站点升级先预览：`dsh-plugin-manager migrate-site --root <站点根> --config <配置>`；确认后加 `--apply --stopped-file <停写证据>` 完成一次性迁移，物理搬迁用 `--rebind`（同样要求 `--apply` 与停写证据）。正常 build 不自动调用它。
- 受管授权集合升级为 schema 3：`siteId`、`profile`、`managed`、`environment`。旧记录只读留作迁移与诊断，日常入口遇到旧 schema 明确拒绝，不当成空安装；`siteId` 或 `profile` 缺失同样拒绝写入。

## 停写证据与锁

- 停写证据按实时引擎查询核对，不接受只填 `stopped=true`；compose 零容器是合法已停现场，但仍须证明没有重叠的可写挂载写入者。
- profile 锁与取锁、残留锁退役、显式解锁共用的 control 锁；不按时间或 PID 猜测锁的归属，无法证明持有者退出就保留锁。

## 删除的恢复语义

- 删除 `--resume`、`--recover`、`--data-compatible`、`--rebuild`、`--rebuild-plugins`、`--container`，以及恢复分支、pending 消费链和旧 worker。这些旗标仍会被**明确拒绝**并说明替代入口，不会静默忽略或混进「未知参数」。
- 失败后直接重新运行普通 build，从当前现场收敛；`check-records` 是只读的现场差异诊断，不再判断续跑，`doctor` 在任何状态下都给出同一条普通 build 命令。

## 页面与验证工装

- 宿主页面回归工装与页面探针可在插件页实跑，跳过的用例不再计为通过。

## 安装与升级

本次附件包含 manager、kit、公共应用、精简部署包、独立起步包和 SHA256SUMS.txt。核对摘要后按[首次部署指南](https://github.com/PelyDeng/dsh-plugin-manager/blob/v0.18.0/doc/first-deployment.md)操作；部署包与起步包也附有离线正文。

升级公开框架文件时保留 `incoming/` 与 `.local/`。旧站点先执行一次性 `migrate-site`，再由普通 build 收敛；原配置、账号和业务数据不自动迁移，optional/auth 更新不会自动替换 incoming 中的认证包。
