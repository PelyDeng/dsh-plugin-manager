# DSH Plugin Manager 0.13.0

本次将 manager、kit、auth、example 改为统一框架发布单元，四个配套产物均使用 0.13.0。定制插件继续维护自己的版本；官方 DSH、第三方依赖以及数据库、schema 和 protocol 版本不变。

## 版本维护

根 `package.json` 的 `version` 是唯一框架版本源。`node scripts/version.mjs set X.Y.Z` 同步四个包和当前版本文档；`sync` 根据已编辑的总版本同步；`check` 只读校验并在遗漏时失败。版本不能倒退。

含当前版本的说明文档使用相邻 `.md.tmpl` 模板和 `{{FRAMEWORK_VERSION}}` 占位符，生成的 Markdown 随源码提交，GitHub、Gitee 与离线阅读均显示具体数字。历史发布记录和功能起始版本保持原样。使用方式见[版本管理](../versioning.md)。

## 自动验证与交付

Check 工作流覆盖 Windows、macOS、Linux 与 Node.js 22、24 的六组组合，执行版本同步校验、版本脚本行为测试以及现有构建、类型、行为和独立归档消费检查。归档消费检查验证四个包的实际版本及管理器 CLI 输出，防止仅修改归档文件名而混入旧包。

Release 标签必须匹配总版本，公共应用清单中的 auth/example 版本也必须相同。交付文件为 `plugin-manager-0.13.0.tgz`、`plugin-kit-0.13.0.tgz`、`dsh-plugin-manager-public-apps-0.13.0.zip` 和 `SHA256SUMS.txt`。此历史发布说明固定使用本次版本，不参与后续模板更新。

## 升级与验证边界

首次统一版本高于此前 manager 0.4.1、kit 0.2.1、auth 0.12.1 和 example 0.6.2。配套组件按一次框架交付整体打包；即使某组件没有业务代码变化，也会产生新版本归档，部署时可能重新安装。按正常部署入口更新，保留既有数据、配置、备份及恢复记录。

宿主继续使用仓库 gitlink 锁定的 DSH 0.1.3-alpha.1，具体提交以本标签的 `deepseek-harness` gitlink 为准。自动工作流不下载或升级宿主，不执行真实模型问答，也不自动部署服务器。CI 通过不代表真实宿主、浏览器和生产验收已完成，这些证据由部署验收单独记录。
