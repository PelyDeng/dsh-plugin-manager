# 熟人试用邀请与反馈清单

维护者自行联系熟人试用。下面的邀请可以直接转发；试用人数、完成情况和反馈不预填，不在社区介绍帖中公开招募。

## 可转发的邀请

我做了一个开源项目 DSH Plugin Manager，是基于 DeepSeek Harness 的 AI 应用开发与部署框架。个人开发者和小团队可以基于 DSH 生态开发自己的各类插件，通过管理器 CLI 和部署流程统一打包、安装、更新与管理，供自己使用或交付给他人，也可以按需复用统一登录和应用授权。

想请你按文档试用一次，看看第一次接触的人能不能顺利跑起来。无需写好评或点赞；哪里看不懂、哪里卡住，都比一句“挺好”更有帮助。

项目：[PelyDeng/dsh-plugin-manager](https://github.com/PelyDeng/dsh-plugin-manager)

先看：[图文导览](quick-tour.md)，准备实际运行时看 [Linux Docker 首次部署](first-deployment.md)。没有合适环境也可以只检查文档，反馈你是否能理解项目用途和下一步。

实际部署需要安装依赖、拉取镜像，并使用自己的模型账号。首次构建时间取决于机器与网络；模型问答可能产生提供方费用。请使用测试环境和测试数据，不发真实密钥、控制台令牌或业务数据。

希望你依次体验：首次登录并改密、创建普通账号并授权、录入模型密钥、普通账号完成一次问答、刷新后恢复历史。愿意继续开发的话，再试一下最小独立 Bundle 的打包流程，以及按[交付指南](../packages/plugin-manager/DELIVERY.md)安装、配置和更新自己插件的流程。

反馈可以直接私下发给我；适合公开复现的问题也可提交到 [GitHub Issues](https://github.com/PelyDeng/dsh-plugin-manager/issues)。

## 反馈清单

| 项目 | 请填写实际情况 |
| --- | --- |
| 版本 | Release 或完整提交号 |
| 环境 | 操作系统、Node、Docker/Compose、安装方式；无需公网 IP |
| 对项目用途的理解 | 用自己的话描述它解决什么问题 |
| 文档理解 | 最先点了哪个入口？哪一步不知道该做什么？ |
| 部署结果 | 完成 / 失败 / 未尝试；记录实际耗时，区分下载与操作时间 |
| 登录与授权 | 管理员改密、普通用户授权、未授权访问各自结果 |
| 模型设置 | 保存和更换是否生效；仅报告结果，不附密钥或指纹 |
| 首次问答 | 是否收到流式回答，刷新后能否找回历史 |
| 独立开发（可选） | 是否完成最小插件打包；卡住的具体命令 |
| 插件管理（可选） | 是否完成安装、配置和更新；原有插件、配置与数据是否按预期保留 |
| 最需要改的一件事 | 具体页面、命令或文档段落 |

报错请提供最少复现步骤、预期与实际结果、经过脱敏的错误片段。记录“未尝试”即可，不要为填满清单使用不熟悉的生产环境。安全问题按照 [SECURITY](../SECURITY.md) 处理。

## 如何整理反馈

维护者在自己的非公开笔记中记录联系人和沟通情况。经对方同意后，将可复现的问题整理为公开 Issue；不要把私人聊天、联系方式或完整运行日志提交仓库。

先处理阻止首次运行、首次登录和首次问答的问题，再看文案与便利性。熟人样本有关系和技术背景偏差，不能把他们的好评当成广泛需求验证。实际独立完成流程的人数和卡点，比邀请人数更有用。
