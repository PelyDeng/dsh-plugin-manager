# 产品定位与独立插件接入设计

状态：设计评审、实现复核及本轮框架接入验收完成。manager 0.3.0 归档已生成，尚未公开发布或同步私有集成库。

## 目标与职责

定位：基于 DSH 的应用接入与交付管理框架。独立作者保留官方插件与 Agent 结构，复用身份、配置和交付流程；部署者无需修改框架源码即可安装应用。内部 `plugins/*` 扫描、选集与 development/link 保留。

| 工作 | 框架复用 | 应用作者负责 |
| --- | --- | --- |
| 登录、应用授权 | 账号、会话、管理员授权、kit 拒绝未授权访问 | 声明认证角色，接入 HTTP/工具鉴权 |
| 数据权限 | 提供可信当前身份 | 部门、客户、报表的数据范围 |
| 配置 | 实例文件位置、读取、部署和挂载 | 业务字段、凭据解析、缺项提示 |
| Agent | 官方 DSH 模型、执行和工具接口 | 工具、提示词、允许的能力 |
| 交付 | 通用 build/check/pack、清单组合、安装及就绪检查 | 包身份、入口、业务探针与说明 |

销售报表场景用于衡量接入价值，不将登录复制或测试拼装视为持续复用。本轮交付框架流程和最小独立示例；真实销售系统、部门数据规则、分析与图表属于具体应用，缺少实际接口时不冒充已完成真实销售查询。

kit 可选。“无侵入”指不修改 DSH 源码；元数据不会自动保护业务路由，不承诺任意社区插件或任意宿主版本兼容，也不宣称这些能力独有。

## 作者入口

```sh
dsh-plugin list --root <作者单包根> --package .
dsh-plugin check --root <作者单包根> --package .
dsh-plugin pack --root <作者单包根> --package . --output <新发布目录>
```

`--root` 必填；`--package` 仅支持 `.`，与 `--plugins` 互斥。显式包即使 defaultEnabled=false 也被处理。list 只读声明，无需锁文件；build/check 使用作者依赖，pack 按包根 pnpm-lock.yaml 冻结安装。外部 install/run/pack 忽略父 workspace，不自动寻找其他包。

不传 `--package` 保持内部扫描、默认选集、all/none、排序、records 和批量任务。单包读取器与任务执行器复用，内部 kit workspace 依赖准备保持。独立示例分别演示无 kit Bundle 与可选 kit 接入，不复制账号或安装实现。

## 必要检查

| 阶段 | 必须检查 | 不追加 |
| --- | --- | --- |
| 读取声明 | 包身份、必需入口声明、合法路径、被声明字段 | 强制页面、工具、认证或探针 |
| 构建/检查 | 通用调用 scripts.build/check，生成可加载产物；必要类型和语法检查 | 登录、模型请求、业务全量测试、部署凭据 |
| 打包/组合 | 归档身份、导出/资源存在、可移植依赖、摘要与私密路径安全 | 再次构建、执行包代码、宿主版本白名单 |
| 部署 | 配置可读、认证提供者、官方安装及宿主/已声明探针 | 管理器理解销售字段或新增业务分支 |

单次 check/pack 只运行一次 build 和 check。auth/example 的完整测试从 check 分离，kit/manager 同样提供独立 test；根 test 先构建再原生递归测试，CI 保持独立测试步骤。已有类型配置不另作重构。

业务字段由应用的 Config/解析器在最早可判断时验证，错误标明应用 ID 和字段名，不包含配置值。管理器在部署前拒绝缺少必需配置文件或认证提供者；业务字段错误由插件启动校验报告，不能承诺管理器在加载业务代码之前识别销售地址。无 healthPath 时明确 not-provided，不能据此称业务已就绪。

## 发布物组合

```sh
dsh-plugin compose-release --root <交付根> --output releases/site-v1 --manifest incoming/auth/manifest.json --manifest incoming/sales/manifest.json
```

组合读取一个或多个已有清单及归档，复用 loadRelease，复制时统一命名为 `<id>-<sha256>.tgz` 并重写 archive，最后写出 manifest.json；不依赖作者源码、Git 或构建工具链。重复插件 ID、包名或运行变量明确拒绝，不自动选版本、不静默覆盖。目标必须不存在或为空，失败时不生成成功清单，不覆盖现用发布物。复制期间出错可留下不完整目录，使用新输出目录重试。

输出清单 2，移除 directory、保留严格校验的 development 元数据用于清除遗留开发环境变量。内部清单 1 继续读取并保留原模式；组合输出与外部单包清单只支持 release。所有有副作用的部署入口先拒绝清单 2 的 development 请求；安装状态、pending 和恢复格式不变。

组合的是完整候选集合，不自动继承现有受管应用。新增第二个应用时输入 auth、第一应用和第二应用的发布清单；更新时替换该应用输入版本并保留其他应用。对已组合的整站清单，不叠加同 ID 新包，使用原始分项清单重新组合。未出现在新候选集合的受管应用会按已有同步规则撤选，数据保留。非受管包不自动接管。

升级时 `compose-release --previous <现用清单>` 额外复制该清单校验通过的旧归档，保留旧 archive 的实际相对路径以解析原有 file: 依赖，不加入新候选集合。相同目标路径且内容不同在写入前拒绝。Compose 将新目录挂载到固定容器位置，宿主上仅保留旧目录不能代替这一步。仅携带现用清单所需归档，不递归收集历史。已有发布目录仍保留供恢复使用。

认证依赖沿用部署时的实例设置检查：每个启用的 authenticated consumer 必须具有唯一、已启用的 provider；已安装但不在候选清单中不算。组合阶段不根据默认值强制认证，因为部署者可以显式选择 standalone。

## 部署者流程与文档

交付物包含：每个应用的 tgz 与原始清单、配置模板、manager/可选 kit 的版本与 SHA-256、匹配宿主的获取说明、组合命令、部署说明。包内 README 自包含核心命令，交付指南说明操作步骤，配置字段只在配置规范集中描述，根 README 仅负责定位与导航。

部署者按指南完成：检查版本 → 组合完整候选集合 → 填写配置/凭据 → 应用并查看就绪 → 首次管理员改密 → 创建普通用户及授权 → 使用应用。重用现有 home 和实例配置进行更新；不让作者手改 Compose 挂载，不把配置值打进发布物。

应用完整组合清单时显式传 `--plugins all`，避免旧 deployment 配置的 plugins 选集过滤新增应用；实例 enabled=false 仍继续生效。保留现有选集优先级，不自动改写部署者配置。

本轮不引入市场、自动下载、来源注册框架、SSO、新账号体系或多租户调度；不发布 npm/GitHub、不部署生产、不自动同步私有集成库。
