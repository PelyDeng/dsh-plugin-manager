# 多建筑与 NPC 机制完善记录

本轮根据用户要求，将建筑和 NPC 纳入当前机制设计，完善相关文档；未开始游戏业务实现、美术素材生成或部署。

## 设计范围与变化

- 当前最小世界设计包含办公楼、咖啡店及双向连接。后续建筑沿用建筑、地图、入口的分层，不复制办公楼房间结构。具体触发格、到达格、返程格仍待地图资产与原型验证。
- 新增 npc_rules.yaml：岗位型 NPC 的目标和完整路径均限制在岗位附近活动区；探险型无固定出生地，可按许可连接跨图。首次放置点不等于永久出生地。
- NPC 各自有人格、表达习惯、被打断反应和对白样例。咖啡店岗位人物、探险人物目前是设计示例，不是用户已确定的正式名单。
- NPC 预写对白不提供自由输入；模型对白需要独立授权的无业务工具通道。两种视图共用唯一交互占用，切图、走远或离场后不把迟到回复投给其他人物。
- 老板外出时任务与常驻管家入口继续。管家和三名业务员工当前活动域仍为 office，不追随老板跨图，不伪造报到。探险 NPC 跨图只移动自身，不切换玩家镜头。
- 地图加载失败、取消、超时留在原图合法位置；未显示地图的 NPC 冻结活动并保存位置，重载不复制身份，不强制探险人物回初次放置点。未引入离屏世界模拟。
- 不因增加咖啡店而增加未指定的货币、物品、购买或经营玩法。

## 第二阶段规则收尾

1. 管家指定派单，独立步骤可并行；依赖步骤留在计划中等待，不占员工。上游尚未终结时等待，实际材料就绪后才派下游；失败无法恢复时明确未执行。
2. 子任务新增逻辑目标、输入版本、依赖、重试／替代来源及真实材料引用。每个目标的替代链唯一、无环，旧记录不可改写。
3. 按当前有效目标结果聚合，成功重试不再因旧失败永久降为部分完成；缺额度或缺适用结果的目标记录为未完成。范围改变后，下游不能继续引用旧上游材料宣称成功。
4. 补充区分表达与范围变化，汇总前核对已接受／已处理版本；正在汇总也能回理解并重新安排。旧任务ID的草稿不能自动开新单。
5. 就近与常驻管家入口共用员工问题选择和回复；理解补充期间收到问题也有合法回复出口，未处理输入不被跳过。
6. 补齐主要机制 Mermaid 流程图，图为主要分支说明，仍以结构化契约为准。

## 证据边界

状态路径只检查图上可达性，依赖和聚合使用规则表；NPC边界样例使用合成路径，不是实际地图几何。自然语言 guard、所有并发时序、真实授权、模型对白、场景帧率和最小原型尚未运行验证。地图连接仍为 pending_layout，不能称建筑已经可游玩。
