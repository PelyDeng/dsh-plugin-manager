# 走近员工只能搭话，不能派活

**状态**：已采纳（用户提出「靠近员工可以单独发话」后确定）

老板走近某个员工，可以跟他说两句话，但这段对话**不产生任务**、不进任务账、不影响正在跑的任务。
如果老板说的其实是活，员工把活推回牛马大总管——「这活你让牛马大总管派给我」。

替代方案是让走近员工直接定向派活（`dsh-pirate-command` 就是这么做的：老板可以直接对某位船员
说话，指挥台把这段交谈纳入当前协作）。那条路更省事，也更直接，但我们没选，因为需求文档把
「统一入口：所有任务只对牛马大总管 Agent 说」列为核心体验，也写进了成功标准。一旦走近员工能派活，
牛马大总管就不再是唯一入口，任务账会漏记，而且「牛马大总管调度」这个卖点会被绕过去。

**为什么不是干脆禁止跟员工说话**：那样办公楼里除牛马大总管之外的三个角色就只是会动的布景，玩家走过去
什么也做不了，世界的可信度会掉。搭话让这三个角色有性格、有反应，又不破坏调度模型。

**代价**：玩家可能会试着对员工派活然后被推回来，第一次遇到会觉得别扭。用台词化解，不用报错框。

**这条容易被"顺手改好"**：后来者很可能觉得「推回来太麻烦了，直接让他接吧」。这个决定写在这里
就是为了拦住那次修改——那会同时打破任务账和需求文档的核心设定。
