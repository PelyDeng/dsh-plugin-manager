# 游戏运行平台与前端技术选型

状态：已确认。

## 首版运行范围

桌面浏览器是主要运行平台，提供完整玩法。玩家使用键盘移动，使用鼠标选择目标并与人物、物体和界面交互。具体键位映射留到交互设计时确定。

移动端仅将Android手机和平板纳入首版可玩范围，不另做虚拟摇杆。触摸地面后人物自动移动到目标位置；触摸人物或物体执行交互。设备连接鼠标时沿用鼠标点击行为。

按2026-09-14用户决定，本次不适配iOS、iPadOS或任何平台的Safari，不安排WebKit专用实现、测试和验收。桌面非Safari浏览器及Android保留原有输入、触摸和横竖屏方案；不以“可能碰巧可用”承诺被排除平台的兼容性。

横屏是Android手机和平板的主要体验。竖屏仍可玩，但采用精简布局：隐藏次要 HUD，任务本和对话框使用全屏弹层。横竖屏共用游戏逻辑和美术资源，旋转后保留人物位置、任务和当前界面状态。

首版不做多指缩放、复杂手势或横竖屏两套独立美术。

## 前端技术组合

游戏使用 `Phaser 4.2.1`。Phaser 负责地图、人物、镜头、精灵动画、场景切换和游戏输入。

界面使用 `Vue 3`。任务本、对话框、HUD、按钮、提示和中文输入框使用原生 HTML 元素及 CSS，由 Vue 负责渲染和交互。Vue 界面覆盖在 Phaser Canvas 上，不把文本输入绘制到 Canvas 中。

状态管理使用 `Pinia`，首版只建立必要的游戏界面 Store，不增加路由或持久化插件。

前端使用 Vite、TypeScript 和 Vue 单文件组件构建，将 Phaser、Vue、Pinia 与寻路依赖打入插件自己的静态产物，不依赖 CDN。插件后端入口继续使用仓库现有的 `tsdown`。首版不引入 Nuxt、SSR 或其它全栈前端框架。

## 移动与寻路

地图使用现有设计规定的 32×32 碰撞网格。键盘输入控制人物连续移动；鼠标或触摸点击目标后自动寻路。两种输入共用移动执行器、碰撞规则和四向人物动画，不使用物理引擎模拟人物或家具推挤。

寻路沿用现有 `map_rules.yaml`：A*、四邻格、曼哈顿距离、禁止斜走。实现采用锁定版本的 `easystarjs@0.4.4`，按帧分批计算并允许取消旧路径；外层适配负责读取碰撞网格、限制单次搜索最多展开 4096 个节点，并把不可达结果交给既有失败规则处理。

## 资源构建

制作源保留 Tiled `.tmj/.tsj`、独立 PNG 与可编辑原生工程。正式构建生成精简地图 JSON 和 Phaser 纹理图集；浏览器不解析原始工程文件，也不逐张加载全部角色帧。运行资源按地图和角色分组并按需加载，预览图、验收截图和 `.pxo` 不进入游戏安装包。

角色图集使用 `free-tex-packer-core@0.3.9` 在构建时生成，采用 Phaser 3 图集格式。禁止旋转和裁边，保留原始帧尺寸并添加必要边距，避免改变人物脚点和像素边缘。该工具仅是开发依赖，不进入浏览器运行包。

地图构建同时读取 Tiled `.tmj/.tsj` 和已验收的 `*.layout.json`。前者提供实际图块和可见层，后者提供区域、工位、入口、NPC、脚点及可通行语义。最小 Node 脚本使用 `JSON.parse` 校验尺寸、32×32 网格和碰撞数据一致，再输出每张地图唯一的精简运行时 JSON；任一来源不一致时构建失败，不静默选边，也不要求构建机器安装 Tiled。

## 状态职责

管家后端仍是业务任务、对话历史、回复、取消和最终结果的唯一权威来源。游戏不能自行推算、覆盖或复制一套业务终态。

Phaser 保存高频游戏状态，例如地图、人物坐标、移动目标、镜头和当前动画。这些状态不逐帧同步到 Vue 或 Pinia。

Pinia 保存浏览器内需要跨 Vue 组件共享的状态，包括任务投影、当前选中人物、弹窗、连接状态和输入焦点。断线重连后，任务投影从管家重新读取。

中文输入使用原生输入框。输入框获得焦点或输入法正在组词时，暂停游戏键盘移动，避免输入文字同时触发人物行动。

## 与管家连接

游戏浏览器直接调用同源的管家 HTTP／SSE 接口，沿用当前登录 Cookie、可信用户身份和权限校验。`/chat`、`/reply`、`/supplement`、`/transcript` 等共享任务接口不经过游戏后端再次代理。

游戏不复制任务正文，不直接访问管家数据库，也不建立第二套业务 API。游戏插件后端只负责自己的静态资源、健康检查及后续明确需要的游戏专属数据。如果真实宿主证明浏览器不能安全直连，再增加最小服务端适配层。

游戏页面使用自己的 `niuma-boss:access` 权限；任务操作仍必须通过管家的身份与权限校验，游戏不代替用户或提升权限。登录失效时使用现有认证入口，不自建登录页。

管家暂时断线或用户没有管家权限时，地图移动、场景浏览和普通 NPC 的预写对白仍可使用；任务入口显示明确原因并禁止新的业务写操作。重连后重新读取权威快照和事件序号，不用本地表现推算任务状态。

## 恢复与重试

`/events` 断开后使用最后收到的 `seq` 作为 `after` 自动重连，间隔依次为 1、2、5、10 秒，之后保持 10 秒上限。收到 `reset` 是正常恢复信号：重新读取 `/task` 权威快照，再从服务端给出的当前序号继续订阅。

`/chat`、`/reply`、`/supplement` 已经发出但响应丢失时，只能在当前页面生命周期内使用原 `requestId` 和完全相同的正文重试。`409`、权限错误、版本冲突与 `run_result_unknown` 不自动重试，改为刷新任务快照并提示用户。`/stop` 不自动重试，先读取当前任务状态，避免误停随后开始的新任务。

页面刷新后不恢复未完成的 POST 请求，也不持久化其正文；只从管家恢复权威任务状态。读取可以自动恢复，写操作保持保守。

## 性能预算

桌面目标为 60 FPS，稳定运行时 95% 的帧不超过 20 ms；Android手机和平板最低保持 30 FPS，95% 的帧不超过 33 ms。最重场景按办公楼 11 人同时存在、角色动画、环境特效和管家 SSE 更新验证。

单帧寻路计算最多占用 2 ms，未完成的搜索留到下一帧继续。Vue 只随业务或界面事件更新，不接收人物逐帧坐标。纹理图集单张不超过 2048×2048；首次只加载出生地图、当前人物和必要 UI，其余地图按需加载。

页面进入后台时暂停 Phaser 渲染；回到前台后读取任务快照并恢复订阅。首版不使用 Web Worker，只有实测寻路或事件处理持续超出预算时才加入。

首包体积不在缺少真实构建数据时预设数字。第八步最小技术验证记录压缩体积和请求构成，再据此设置上限。

## 本地保存与恢复

首版不新增游戏服务端数据库。任务、历史、执行状态和业务结果只保存在管家；浏览器 `localStorage` 仅按登录身份保存玩家当前地图、最后合法格子、朝向和少量界面偏好，不保存任务正文、Cookie、鉴权令牌或业务结果。

加载本地快照时重新校验地图、碰撞和许可范围。快照缺失、版本不兼容或位置失效时回到该地图的安全出生点，不修改管家任务。NPC 的临时位置、路径和动画在刷新后按地图规则重新生成。换设备不继承人物位置，但仍通过管家继续同一任务和历史。

## 运行模块

`PluginServer` 注册 `/niuma-boss` 页面、静态资源和健康检查，不代理管家任务。`ButlerClient` 是唯一了解管家 HTTP／SSE、入口发现、契约版本、`requestId`、事件序号和重连规则的模块。

`GameSession` 是浏览器运行时的核心深模块，对外只提供启动、处理用户意图和停止；内部把管家事件转换为 Pinia 界面投影及 Phaser 场景表现命令。`GameWorld` 封装 Phaser 地图、人物、寻路、镜头和动画，不读取业务接口。`GameUI` 封装 Vue 与 Pinia，不保存人物逐帧位置。

`web/main.ts` 只负责创建并连接这些模块，不放业务规则。资源转换脚本属于构建工具，不作为运行模块。HTTP、游戏循环和界面之间不互相穿透。
