# 游戏与管家共享任务接口确认清单

致 `dsh-butler-console` 维护同事：

牛马-老板游戏进入第四阶段架构设计。游戏会作为独立插件运行，优先复用现有管家的任务理解、员工调度、结果收集和历史管理。现有群聊窗口继续由你们维护。以下用于确认可复用接口与协作范围，不要求重写现有实现；已经具备的能力请直接给出当前契约与验证方式。

## 一、已确认的产品决定

- 同一可信用户在游戏和群聊中共享同一份任务与历史，能够在另一入口查看并继续处理，不创建任务副本。
- 管家持有业务任务的权威状态；游戏负责地图、人物、镜头、动画及交互呈现。演出不推进业务终态。
- 两个入口执行相同的身份、权限、任务状态与幂等校验。界面切换不改变任务或会话归属。
- 共享业务任务不等于合并所有员工/NPC 的对白会话。独立闲聊通道另行设计。
- 游戏不导入管家插件的私有源码，不直接写其数据库，也不在游戏中复制一套调度器。
- `butler/executors` 是员工执行入口登记契约，不代替游戏调用管家任务管理的接口。

## 二、本地代码核对到的现状

核对日期：2026-09-13。依据本地 `plugins/dsh-butler-console/src/`；同事正在持续完善，请以你们确认的最新版本为准。本次未进行线上请求或完整业务测试。

下表使用默认入口 `/butler` 表示当前 `config.routePrefix`，最终客户端不应假定前缀永远固定。

| 已有入口 | 本地可见行为 | 尚需确认 |
| --- | --- | --- |
| `GET /identity` | 返回身份模式、标识及登录入口 | 游戏访问时的登录、权限与会话失效契约 |
| `GET /members`、`GET /overview` | 成员与概览信息 | 在线、可派活、忙碌、等待回复等状态如何准确区分 |
| `GET /conversations` | 会话列表 | 会话创建/恢复方式及完整对话内容读取入口 |
| `GET /history` | 任务历史，支持分页、关键字与状态筛选 | 活跃任务发现、分页一致性与新增状态兼容 |
| `GET /task?id=…` | 单次任务、子任务及结果 | 是否足够作为重连恢复的权威快照 |
| `POST /chat` | 接收 `conversationId`、`message`，返回 POST SSE 流 | 当前响应连接关闭会调用 `cancel`；执行生命周期与页面连接如何分离 |
| `POST /reply` | 接收 `taskId`、`subtaskId`、`text` 或 `decideByAgent`，返回 SSE | 跨入口恢复回复、重复提交、连接关闭与执行结果如何处理 |
| `POST /stop` | 接收 `conversationId`，调用取消并返回 `{ok:true}` | 如何精确取消原任务，避免迟到操作影响该会话的新任务 |

本次核对的上述请求处理函数没有接收通用 `requestId`；没有发现独立于 `/chat`、`/reply` 执行请求的任务订阅入口。现有 `TaskState` 为 `queued/running/waiting_user/summarizing/completed/failed/cancelled`，不包含游戏机制已定义的 `external_pending`。这些是对齐点，不代表同事尚无相关计划。

## 三、请逐项确认的接口能力

P0 表示共享任务联调前必须确认；P1 表示首版整体接入验收前确认。具体接口名、通信实现和字段名可以沿用已有规范，以下描述必要语义。

| 编号 | 优先级 | 能力 | 需要确认的契约 |
| --- | --- | --- | --- |
| C01 | P0 | 接入方式与兼容性 | 游戏通过哪些稳定接口调用管家？优先确认现有同源 HTTP 接口是否可支持第二客户端；若有正式宿主调用接口也可采用。给出入口发现方式、鉴权方式、契约版本及兼容规则。 |
| C02 | P0 | 共享身份与归属 | 同一用户从两个插件访问时如何映射到同一任务所有者；归属由服务端可信身份确定，客户端不能用 `owner` 或 `actor` 冒充。明确无登录、权限不足、登录撤销和跨用户访问的响应。 |
| C03 | P0 | 会话、回合与任务标识 | 明确 `conversationId`、一次交互回合、`taskId`、`subtaskId` 的关系、生成方和稳定性。理解需求但尚未形成任务时，第二入口如何恢复该轮内容；完整材料与员工原会话如何关联。 |
| C04 | P0 | 提交需求与执行生命周期 | 提交后返回可追踪的接受凭据及后续任务关联。切换入口、关闭一个观察窗口或订阅断线不应自动取消已经接受的业务任务；显式取消、执行超时与权限撤销另按约定处理。需对齐当前 `/chat` 断线取消行为。 |
| C05 | P0 | 查询与恢复快照 | 提供当前用户的活跃任务、历史分页、任务详情、必要对话内容和完整材料。快照应包含恢复所需的权威状态与版本/游标信息，第二入口打开即可恢复，不能只能依靠发起页面内存。 |
| C06 | P0 | 独立订阅与重连 | 支持两个入口同时观察同一任务，新增观察者不得重新执行任务。约定事件身份、顺序、关联 ID 与去重方式；断线后可续传，或明确要求重取快照。快照与订阅交接不能丢事件；正文增量与最终全文的追加/替换规则明确。 |
| C07 | P0 | 补充需求与回复员工 | 区分新派活、补充当前目标和回答指定员工的问题。定向回复绑定原任务/子任务，检查 `reply` 能力及有效问题；问题缺失时不得编造或改走新任务。两入口均能读取必要上下文并继续操作。 |
| C08 | P0 | 幂等与双入口并发 | 约定请求幂等标识及预期版本或等效并发判定；相同请求重复提交返回同一结果，同标识不同正文拒绝。两个入口同时回复/取消/补充时由服务端原子裁定，冲突应返回可识别结果，不能重复派单或静默覆盖。 |
| C09 | P0 | 取消、超时与迟到结果 | 取消应绑定准确的任务/执行尝试，明确“收到取消请求”和“执行已停止”的区别。重复取消安全；旧任务迟到的取消或结果不影响新任务。确认执行停止前怎样保留员工占用；服务重启怎样收敛运行中的任务。 |
| C10 | P0 | 结果、材料与终态映射 | 明确管家状态与游戏状态的映射，尤其 `waiting_user` 的含义、部分完成和 `external_pending`。博客材料待外部采用/发布时不显示业务成功；按既定机制允许本轮结束并派新活，同时保留材料、原始状态和外部待办。核实员工结果中材料引用、`question`、原会话链接的传递与持久化。 |
| C11 | P1 | 成员能力与可用性 | 稳定 `agentId` 与别名分离；区分已安装、在线、可派活、忙碌、隔离占用和可回复。无执行入口的成员可在场但不能派活。在线状态或工作动画不能代替真实业务状态。 |
| C12 | P1 | 错误、限额与可定位性 | 给出输入限制、并发范围、超时/重试策略和可识别错误码；区分权限不足、冲突、幂等冲突、入口缺失、无效状态、限流和暂不可用。日志能用任务/请求关联标识定位；对客户端不暴露凭据、内部堆栈或未经允许的内部推理。 |

游戏的任务范围、并发限制及用户权限仍按产品已定规则执行，不因为换了入口扩大能力。以上也不授权游戏增加业务工具、博客采用/发布确认按钮或绕过员工自己的权限检查。

## 四、建议共同验证的场景

| 场景 | 预期结果 |
| --- | --- |
| 游戏发起，群聊打开 | 两边看到相同任务 ID、计划、进度和结果，仅发生一次执行。 |
| 群聊发起，游戏打开 | 游戏恢复同一任务，无需复制记录或重新派活。 |
| 任务执行时关闭一个入口 | 已接受任务按服务端策略继续，另一入口正常观察；关闭页面不被误当作用户取消。 |
| 断网重连或刷新 | 能重取快照/补齐事件；任务、正文、材料不丢失、不重复追加；订阅不会重跑任务。 |
| 理解阶段尚未生成任务时换入口 | 已接受输入及当前回合能够定位，不能因缺少 `taskId` 丢失或重复执行。 |
| 两入口同时回复同一问题或重复提交 | 最多接受一次对应业务操作，其余返回原结果或明确冲突，两端随后恢复一致。 |
| 执行中补充目标 | 最新已接受输入有版本或等效顺序依据，汇总不会用旧结果覆盖新要求。 |
| 一个入口取消，另一个继续观察 | 两边显示相同取消进度；未证明停止前不谎称停止完成，旧取消不影响新任务。 |
| 博客交回待采用/发布材料 | 两边保留材料并显示待外部处理，允许新派活，不将其显示为发布成功。 |
| 切换用户、登录失效或伪造任务 ID | 无法读取/操作其他用户任务；撤权后的读取、订阅和执行按一致策略处理。 |
| 服务重启或旧执行迟到返回 | 明确恢复或终结状态；旧事件不篡改新任务，不遗留无限忙碌或伪造成功。 |
| 员工不可用或不支持回复 | 两入口一致提示可用能力，相关操作禁用且原因明确。 |

## 六、职责与本次范围

管家侧维护权威任务、调度、记录与对外契约；游戏侧维护独立插件、场景表现及接口消费。共同确认状态映射、双入口生命周期、权限和验收结果。群聊前端内部布局、游戏引擎选型、普通 NPC 动作以及独立闲聊实现不在本次接口清单中展开。

本清单仅用于用户转交同事确认。未修改群聊或员工代码，未发送外部消息，未部署服务器；HTTP、宿主调用接口和共享模块的最终选择仍待反馈。

本地核对依据：`src/index.ts` 的管家与存储创建，`src/web.ts` 的现有路由和流连接生命周期，`src/butler.ts` 的事件定义，`src/task-model.ts` 的状态集合，以及 `src/protocol.ts` 的员工执行契约。既有游戏决策见同目录 `20260913-121147-独立游戏插件与共享管家任务决策.md`。
