# 第四阶段：技术架构与接入——确定“用什么技术、怎样组合实现”

这是当前正在进行的阶段。

| 步骤 | 需要做什么 | 为什么要做 | 当前状态 |
| --- | --- | --- | --- |
| 1. 确定系统分工 | 游戏独立运行，管家负责权威任务、调度和业务编排，游戏负责地图、人物、镜头、动画与界面交互 | 避免游戏重复建设管家调度能力 | 已确认 |
| 2. 确定共享关系 | 游戏与群聊共享同一可信用户的任务和历史 | 用户换入口后能继续同一件工作 | 已确认 |
| 3. 约定管家接口 | 明确入口发现、提交、查询、订阅、回复、补充、取消和正文读取 | 让游戏与管家可以稳定协作 | 清单已完成，主体接口已实现 |
| 4. 验证接口与数据一致性 | 检查并发、幂等、补充收尾、身份归属、迁移回滚及真实链路 | 防止重复派活、任务丢失和错误结账 | 部分完成：六项独立检查通过；同事报告 HTTP 双客户端 16 项通过。迁移回滚、`inputRefs`、安全重试后的依赖重判及游戏浏览器双入口仍待验证 |
| 5. 确定首版运行平台 | 非Safari桌面浏览器提供完整键鼠玩法；Android手机和平板支持点击移动与交互，横屏为主要体验，竖屏使用精简可玩布局 | 为渲染、布局和输入方案提供依据 | 已确认；2026-09-14用户明确移除iOS/iPadOS与Safari适配 |
| 6. 选择技术方案 | 使用 Phaser 4.2.1、Vue 3、Pinia、Vite、TypeScript、EasyStar.js 和构建期纹理图集；地图由 `.tmj/.tsj` 与 `*.layout.json` 共同编译 | 在体验、开发成本、资源加载和维护成本之间作选择 | 已确认 |
| 7. 完成详细技术架构 | 明确运行模块、数据流、状态归属、本地存储、权限降级、断线恢复、写操作重试和性能预算 | 让开发者知道每项能力在哪里实现 | 已完成设计；第 8 步本轮实测结论为部分通过 |
| 8. 技术验证与实施计划 | 用最小技术验证检查 Phaser 与 Vue 叠层、地图编译、图集、输入、横竖屏、性能、范围内浏览器兼容、构建封包、健康诊断及真实鉴权 HTTP/SSE，再拆分第五阶段任务 | 避免正式开发后才发现关键方案不可行 | 本轮结论与计划编制完成，Chromium/Edge通过；Android真机、范围内真实输入及登录链路仍待验证；Safari不再属于适配或验收范围 |

## 审查结论

八个步骤已经覆盖职责、数据所有权、接口、接口验证、运行平台、技术选型、详细架构及开发前验证，没有缺少需要单独列出的顶层步骤。

浏览器兼容基线、插件构建封包、健康诊断和真实鉴权链路属于第 8 步技术验证，不另拆新步骤。第 4 步剩余事项继续保留，不能被技术选型完成替代。

第 8 步本轮验证报告已收口，iOS/Safari适配及相关验收门槛已按用户决定删除。后续仅按当前平台范围补齐真实输入、Android设备、登录链路等缺口；本轮到报告与计划交付为止。过程和产物位于 `docs/09-实施计划/技术验证/`，生成物通过 Git 忽略规则排除提交。第五阶段尚未授权或开始。
