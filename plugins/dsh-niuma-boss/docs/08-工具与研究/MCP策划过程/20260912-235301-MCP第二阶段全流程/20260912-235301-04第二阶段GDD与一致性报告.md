# 牛马-老板：MCP 流程对照 GDD

依据实际读取的 game-full-workflow 1.0.10，完成模块识别、内容归类、六维一致性检查和四部分组装。此稿是第二阶段对照产物，由 AI 按 MCP 工作流撰写；不替代项目的权威契约，也不表示已有游戏、模型或浏览器验收。

## 第一部分：项目总览

牛马-老板是桌面网页上的多 Agent 像素职场游戏。玩家当老板，用走路与说话安排真实工作，观察员工和建筑 NPC 的反应，并查看真实成果。体验关键词是掌控、轻松、人物感；不通过贬低玩家或压榨员工制造乐趣。

平台沿用 Phaser 4 和 DeepSeek Harness。办公楼与咖啡店组成当前最小世界，保持高精美像素风和清楚的文本阅读。探索与成就感只是本轮设计假设，未做受众调研，不由此增加排行、奖励或付费系统。

核心循环是“向牛马大总管说目标 → 牛马大总管指定员工处理 → 自由观察、阅读或去咖啡店 → 查看真实成果与待办 → 安排下一件事”。用户已有边界见[输入与创意框架](./20260912-235301-00输入与创意框架.md)，系统与空间细节见[系统策划](./20260912-235301-01系统与空间策划.md)。

## 第二部分：核心机制

### 操控与任务

方向键控制老板；派活有走近牛马大总管和常驻入口两条等价路径。员工与NPC不自行抢活，NPC交谈不生成业务任务。同一老板最多一轮运行或收尾中的任务。

牛马大总管按职责、执行入口、授权与容量指定执行者。独立步骤可并行，顺序步骤必须拿到真实前置材料。补充改变范围时，旧结果保留但不能完成新要求；重试根据最终有效目标判断，不删除失败历史。详细可编码规则使用既有任务协议，不从通用 GDD 模板另造状态。

### 过程与反馈

业务和表现各自推进。派单可以触发出发，但员工到达不表示执行成功；结果可以先于走路完成。无进度回调时只显示已知状态，无增量时直接呈现真实最终正文，不能模拟模型逐字返回。

玩家看到的是“发生了什么、我接下来能做什么”。已派出可等待或补充；真实结果可展开核对；待外部处理允许开新任务，但必须保留材料和未完成事项。长正文独立于短气泡，不为了像素风删掉来源、错误或结果内容。

### 世界与人物交互

办公楼是安排和观察工作的场所，咖啡店是空间变化与NPC交流的场所。出入口须先有合法落点和返程；失败保留原图位置。老板外出不暂停任务，业务员工当前仍留在办公楼。

岗位NPC的整条路径受附近活动区限制；探险NPC没有固定出生地，按许可入口跨图，不带走玩家镜头，离屏不逐帧模拟。预写对白使用无自由输入面板；模型对白只有独立授权的无业务工具通道可用时才允许输入。忙碌员工只显示业务状态，不能因为NPC可交谈就开放员工忙时闲聊。

### UI 线框意图

```text
┌ 当前建筑与地图 ─────────────── 牛马大总管入口 ┐
│ 人物、岗位、可用出入口、就近交互提示     │
│ 地图不因任务回答而被整块聊天界面永久遮住 │
├ 当前任务的真实阶段／结果入口 ──────────┤
│ 按需展开正文与待办；输入时焦点归当前会话 │
└──────────────────────────────────────┘
```

这是信息组织示意，不规定像素布局或新增面板框架。任务入口与结果可达，地图与正文能相互返回，具体布局交给后续原型。

### 不适用模块

没有战斗、等级成长、背包、装备、经济、抽卡、付费、竞争社交或强制云存档。模板中相应章节标不适用，不用职场惩罚或咖啡店经营来凑齐。

## 第三部分：游戏内容

核心人物为老板、牛马大总管和三名业务员工。example 的执行入口延期；closedoff 只读查询；blog 交付候选，采用与发布仍在原页面。人格与外观可以创作，能力不能跟着改。

MCP人物模块提出“阿禾”“小路”等暂名与剪影方向，属于对照建议，未纳入正式名单。其对忙碌闲聊的笼统表达已在本组装稿收窄：仅NPC或空闲且通道可用的员工可交谈，正在干活的员工不开放闲聊。

首次体验建议由熟悉牛马大总管入口开始，随后观察岗位、选择阅读或出门，再于任意地图查看真实成果。不是必须完成的教程关，不锁出口，不给倒计时或奖励；结果提前回来就先看，不为演出等咖啡店对白结束。

美术交付包括人物识别、基础动作、建筑地面与边界、门口与岗位标识、对白和任务文字视图。声音可在第三阶段评估，不要求每项交互有专属音效。实图、音效、动画和场景均未生成。[人物叙事与资产模块](./20260912-235301-02人物叙事与资产衔接.md)保留原始建议与自检记录。

| 文件 | 负责内容 |

### 状态机汇总

- 牛马大总管：位置与职责并行，回位不阻塞处理；需要补充时记录具体问题，所有工作结束后才能汇总。
- 员工：位置与工作并行，业务终态立即投影，不等动画；外部未知执行另保留隔离。
- 地图：稳定 → 加载 → 提交新位置或恢复原位置，不改变任务归属。
- NPC：未显示、待机、移动、交谈、转图按角色活动权限变化，探险不因此有固定出生地。

本稿不重列每条转换。既有机制流程图与 YAML 才是详细依据，避免两份状态表独立演化。

### 术语

派活：老板向牛马大总管提出目标；派单：牛马大总管指定执行者；报到：人在位置上到达；交差：返回真实材料与本轮状态；待外部处理：游戏本轮已结束、外部采用或确认未完成；岗位活动区：限制一般NPC整条路径的附近区域。继续采用现有 CONTEXT.md 的标识，不按通用模板改名。

### QA 与阶段边界

[技术数值与QA模块](./20260912-235301-03技术数值与QA策划.md)列出重点用例。规则数据校验可复跑，但不能替代真实模型、权限、几何、浏览器和初次玩家观察。第三阶段制作素材，第四阶段落实接入，之后再运行原型与真实业务验证；本轮没有推进部署。

## 六维一致性检查与冲突处理

| 维度 | 对照发现 | 处理与结论 |
| --- | --- | --- |
| 数值自洽 | 通用模板使用米/秒、战斗或经济参数，项目使用格/秒与毫秒 | 沿用项目参数；没有对应玩法的数值不适用，不迁入默认值 |
| 角色一致 | 对照稿重新给closedoff窄轮廓、牛马大总管便笺夹和NPC暂名；原角色已有美术方向 | 作为未采用建议保存，不替换已定人物；不把新称呼当正式名单 |
| 字段一致 | 模板的float/vector3/range示例不等于标准JSON Schema；强制共享全部配置会把地图几何带到后端 | 保留现有标准Schema及前后端职责，未引入第二套字段 |
| 状态机一致 | 对照叙事“忙碌不阻止闲聊”过宽；系统“已开始”也可能被理解成不存在的确认回调 | 改成忙碌员工只读状态；展示已派出和实际进度，不编精确开始信号 |
| 经济闭环 | 无经济需求，咖啡店只是场所与NPC | 不适用，不能以缺章节为由增加购买、货币或经营 |
| 术语统一 | 通用模板的任务/关卡/Boss语义与本项目可能混淆 | 使用老板、牛马大总管、派活、派单与外部待办，不将“老板”解释成战斗Boss |

### 精确性与完整性判断

四部分和适用模块已组装；战斗与经济明确不适用，实际美术、音频及接入列为后续交付而非完成。现有真实协议约束优先于模板简写。没有凭空为岗位半径或素材尺寸填默认值，也没有把文档检查写成实现验证通过。

本轮组装结论：适合作为第二阶段的流程对照稿。它帮助看见玩家路径与模块衔接，但不足以替代已有的精确任务契约。合并应限于首次体验、状态反馈、建筑用途这几处说明。
