# 牛马-老板：系统与空间策划

本稿由当前 AI 按实际 MCP 取回的 `game-system-design`、`game-level-design` 三阶段工作流生成，服务为 `@chantezy/mcp-game-design 1.0.10`。MCP 提供技能正文，未自行推理生成本方案。输入仅为本目录的《输入与创意框架》，未读取既有机制正文；以下取舍是供后续对照的建议，不代表新增需求已获确认。

## 一、系统策划

### 第一阶段：需求大纲

目标是让玩家用一句话安排真实工作，看懂谁在处理、事情到哪一步，并能核对成果。游戏属于多 Agent 像素职场体验，核心关键词为“牛马大总管派活、真实交付、自由走动、人物回应”。

牛马大总管是唯一派活入口，员工依职责接到安排，不抢单。探索与交谈填充等待体验，但不成为工作的前置条件。参考方向来自 brief 的“开口有安排 → 等待可探索 → 成果能核对 → 再安排下一件事”，不据此引入任务奖励或成长循环。

### 第二阶段：细化方向

| 方案 | 玩家体验 | 风险与取舍 |
| --- | --- | --- |
| A：围绕牛马大总管的工作循环 | 常驻入口完成派活、补充和查阅；角色演出解释谁在做事 | 容易像普通聊天工具；用职责明确的员工反应和可见空间补足人物感，作为主体 |
| B：围绕办公室走访 | 玩家通过走近员工和岗位理解分工，再找牛马大总管安排 | 容易变成强制跑腿，误以为员工可直接接单；只保留可选观察和对白，不增加派活入口 |

轻量选择 A，并借用 B 的岗位辨识。乐趣来自“我安排的事确实有人处理”，而非角色忙碌动画本身。看不到正文增量时，不制造假打字和百分比；角色表现与业务事实冲突时，以事实为准。

### 第三阶段：完整策划摘要

| 模块 | 玩家行为与反馈 |
| --- | --- |
| 派活 | 输入目标后，由牛马大总管分析并指定职责匹配员工；先区分已收到与已开始，不能用一句应答冒充执行成功 |
| 进行中的工作 | 查看当前负责人和已有材料；独立子任务可并行，顺序步骤须拿到真实前置材料 |
| 补充与异常处理 | 明确补充是否已接受、接下来如何处理；取消、超时、重启与重试保留已接受信息和可用成果 |
| 交付 | 用简短说明指出结果与剩余事项，完整正文可展开阅读；气泡不承担长文存储 |
| 走动与交谈 | 切换建筑不打断工作；预写对白与真实模型内容可辨识，未授权自由交谈通道时不伪装开放能力 |

同一老板最多有一个运行或收尾中的任务。已有任务未结束时，入口应解释当前情况，不能悄悄启动第二个任务。这里描述玩家可见规则，正式状态名、转换和配置归技术规范对接，避免再造一套状态实现。

业务入口遵守已确认范围：example 首版执行入口延期，不作演示成功项；closedoff 只查询授权园区数据；blog 查询博客并产生真实候选，采用与发布确认留在原页面。博客材料交回后，本轮以“待外部处理”结束，材料和待办可再查，玩家可以派新活；没有外部发布证据就不显示“发布成功”。

首次体验是一条可随时中断的建议路径：玩家在办公楼看见牛马大总管与岗位，打开常驻入口安排一件实际可用的工作；收到真实反馈后，观察对应员工的反应；等待时可继续阅读，也可去咖啡店看场景对白；结果一到即可查阅，无须先返程或等角色走完。交付后看清成果与待办，再决定下一件事。未接入真实能力时，只呈现可用内容和入口状态，不以预写答案替代业务。

界面把“人物在移动”与“工作在处理”分开表达。没有新进度就保持最后一次可信信息，不把沉默解释为失败。结果先到先显示；输入文字时方向键不驱动角色，长文阅读能返回地图，并保持当前工作可达。

必要资产为牛马大总管、职责员工和一般 NPC 的可辨识外观与基础动作，岗位标识、常驻入口、工作摘要、正文面板及异常提示。无需为每种业务状态制作专属动画；正式人物名单、动作规格与文案由后续角色、美术产出衔接。

## 二、关卡与空间策划

### 第一阶段：需求大纲

本项目没有通关阶段，关卡技能原本对纯社交、无阶段游戏不适用。本稿只借用其空间规划与体验引入方法，不套用挑战关卡。

空间目标是让玩家理解两栋建筑的用途，找到可用入口，切图后仍能安排和查看工作。关键词为“办公楼、咖啡店、岗位活动区、合法入口、镜头归属”。参考方向是小型可探索场景：办公楼承载工作关系，咖啡店提供空间变化与 NPC 交流。

### 第二阶段：细化方向

| 方案 | 动线 | 风险与取舍 |
| --- | --- | --- |
| A：双建筑自由往返 | 办公楼岗位与出口有清楚标识，咖啡店入口及返程位置容易辨认 | 对入口几何和跨图位置要求明确；符合既定边界，采用 |
| B：首次访问顺序导览 | 依次认识牛马大总管、岗位、咖啡店，再回办公楼看成果 | 容易把引导变成解锁链；只借用可选提示顺序，不锁出口、不设完成条件 |

采用 A，以建筑标识和岗位标识提供两类视觉线索。无需增加垂直空间、捷径机关或寻路挑战。首次看不懂用途的风险，优先通过标识和一句场景对白解决，不增加导航任务。

### 第三阶段：完整策划摘要

办公楼的建议动线是“出现位置 → 能辨认牛马大总管与岗位 → 可自行靠近观察 → 看见出口”。具体格位仍待地图制作；不能先宣布某扇门可进入，再补做碰撞与落点验证。牛马大总管常驻入口始终可用，玩家无需走到牛马大总管身边才能安排工作。业务员工暂留办公楼，老板去咖啡店不改变员工职责。

咖啡店的建议动线是“合法入口落点 → 可辨认的 NPC 停留区 → 自由走动 → 可找到返程入口”。它提供观察、场景对白和等待中的空间变化，不承担经营、消费、精力恢复或任务交接。交谈不堵住通道；没有自由输入授权时，只展示实际提供的对白方式。

可将技能的四拍方法轻量翻译为：引入时看懂牛马大总管入口；练习时自行查看工作或走近岗位；变体是在咖啡店使用同一个入口；综合是人在任意建筑收到并查阅真实成果。这是体验观察顺序，无强制练习次数、倒计时、奖励和通关判定。

一般 NPC 在职责出生点或岗位附近活动，路径全程合法，不能只检查终点。探险 NPC 可经允许入口跨图，无固定出生地，但不能带走玩家镜头。离屏保留身份和合法位置，不逐帧模拟。正式岗位区域、入口配对、地图尺寸及停留参数均与既有参数衔接，本稿不另设数值。

必要场景资产为办公楼与咖啡店的地面、边界、门口、岗位及活动区可辨识物件，两处场景的文字标识，以及可共用的入口提示、对白气泡和交互反馈。音效与地图美术待制作，暂不规定数量或采购清单。

本稿只有设计推演，未做原型、几何、键盘焦点、真实 Agent 或浏览器验证。后续至少观察首次用户能否分清派活与交谈、跨图是否保持工作可达、结果是否及时显示，并实际检查入口落点与完整 NPC 路径；不能以文档规则代替通过证据。
