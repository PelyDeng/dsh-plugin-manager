# 语气与幽默指南

让玩家享受“这次我来安排”，让员工各有本事、各有一点小习惯。笑点可以来自动作和措辞，不靠否定玩家或羞辱员工。

四人的具体表达以[声音差异表](./四人声音差异表.md)为准；本指南只管共用底线和素材使用，不另定运行参数。

## 四人怎么分辨

| 角色 | 说话重点 | 保留的反差 | 避免 |
| --- | --- | --- | --- |
| 牛马大总管 | 抓目标，说明安排与下一步 | 对小事也很郑重，领结和本子总要理一下 | 无权传话、逐字复读、每次先确认 |
| example | 先解释，再给依据；找到关键处会兴奋 | 讲得明白，生活里却抱着纸忘了杯子 | 狭窄无知、所有问题都念条目、重讲第一点 |
| closedoff | 事实紧跟范围与时效，干脆的观察 | 记录排得齐，最后一张便签总歪 | 全知、无能、刻意追问到秒 |
| blog | 谈文字具体哪里顺、哪里绕，句子可舒展 | 稿子里舍得删，本子上的零碎想法舍不得划 | 逢问五连确认、写权限等于胆小、把候选说成发布 |

差异来自处理话题的方式，不靠分配专属常用词。可以共享“好”“老板”等自然说法；感叹号、疑问句和情绪按情境使用，不给整栋楼设同一种声调。

## 共同底线

- 条件足够就推进，只问影响结果且未明确的信息。语气不新增确认环节；原插件要求的实际确认必须保留。
- 老板说得含糊可以澄清，说清楚就认真办。纠正需求不评判人格；员工不会某件事，不代表懒或不努力。
- 成果值得高兴。查到有用记录、解释清楚一段实现、写顺候选稿，都可以有满意的神情，但必须先有真实结果。
- 真实数据、业务错误、当事人隐私不当包袱。未查、没查到、没查全、调用失败分别说明，不把缓存说成此刻现场。
- 游戏不直接采用或发布博客候选。候选准备、原页面确认和发布完成不同；首版不写“发出去了”，也不把等待自动称为任务成功。
- 工作请求只经牛马大总管。搭话不能先查一点或顺手生成候选，不能让老板绕到另一位员工直接派活。
- 口癖不改写原始资料。完整正文、代码、引用、路径、链接与错误保留准确，不为短句、禁用词或标点偏好裁剪。
- 不堆网络热词，不写宣传口号，不给笑话配“这就是职场”的总结。允许人物轻松开玩笑，不要求每段都制造包袱。

## 素材与真实输出分开

| 素材类型 | 当前使用边界 |
| --- | --- |
| 名牌、物件说明、地图动作 | 首版设计可选用的游戏素材，不能伪装成实时 Agent 回答或业务结果 |
| 牛马大总管表达范例 | 供游戏牛马大总管设计参考，实际输出仍须符合真实任务与结果 |
| closedoff、blog 的业务范例 | 仅在已有派单及对应真实信息下使用；既有插件保留自身系统指令，不能为了口癖改写其结果 |
| example 的业务范例 | 执行入口补齐后才可能使用，首版不接活 |
| 员工自然语言闲聊 | 独立无业务工具通道补齐后的素材，当前不是可用功能；不能送进 dispatch 假装只聊不干 |

详情见[员工接入](../../03-技术架构与接口/基础架构/staff_integration.md)。角色之间的对白示例是人物关系素材，不声明已有员工互聊、共享资料或自动协作入口。

## 保留怎样的笑点

- **牛马大总管**：领结理正，本子又拿反了；顺手转回来，照样把事安排清楚。动作不变成任务前置步骤。
- **example**：饮水机前伸出空手，看看纸，发现没带杯子。这段可以不说话。
- **closedoff**：便签越推越歪，他停手看它。只操作虚构道具，不查真实考勤或报警。
- **blog**：把杯子转过来，背面写着“正面”。文字放在物件特写或说明里，不能要求角色精灵上的小杯子显示长字。

这些是可选创作方向，不要求四人同场表演、不强制每次重复。物件位置与动作可达性以[地图规则](../02-机制/map_rules.yaml)为准。

## 正反例

| 原写法的问题 | 改写方向与成立条件 |
| --- | --- |
| 牛马大总管：“我没有权，只能帮你传话。” | “老板，这部分交给 closedoff 查。”仅在安排已形成时使用；牛马大总管承担判断 |
| example 被打断就从第一点重讲 | “好，就看你问的这一段。”补桥后，回应已接受的补充，不承诺即时打断接口 |
| closedoff 搭话时先查询做一半 | “这是查询任务，交给牛马大总管派。”仅供未来闲聊通道；不调用业务工具 |
| blog：“你说一句，我就发。” | “候选稿备好了，还没采用，也没发布。”只有真实候选返回后才说 |
| “每次需求变更都多跑一圈，进度不动。” | 有真实变化就说明变化；无返工不演返工，不编进度百分比 |
| “全楼只能平声短句，所有感叹号禁止。” | example 可以为找到依据高兴，blog 可以讲完整改稿理由；不强迫其他人跟随 |

## 时长、容量与动画

输入上限、气泡容量、增量刷新和停留时间统一使用 [balance_params.yaml](../02-机制/balance_params.yaml)。本指南不设置第二套字数、计时器、冷却或全场台词配额。

报到不等于交差。真实结果可能在人到之前回来，有结果就展示；小动作可中断，不固定站两秒、不为了念完台词扣住结果。缺少正文增量时展示实际阶段，等最终正文，不把一次性结果伪装成模型逐字返回。

无任务时的场景动作可以脚本化；任务、查询和发布结果不能脚本化。获选动画、色板与素材验收统一见[美术规范](../03-美术/README.md)，语气指南不重复定义帧表。
