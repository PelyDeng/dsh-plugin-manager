## 像素、帧与脚点

- 地图格为 **32×32 px**，角色目标单元为 **32×48 px**。既有源画布包含 48、64、68 px 等尺寸；新素材也须保留原图并先核对可见范围，再修整与对齐，不能压扁或裁肢来适配。
- 游戏采用 south、west、east、north 四正向。生成的斜向原图保留在来源中，不增加斜向游戏移动。
- 优先使用现有 **128 色基础色板**中的浅冷色表现新办公楼。若实测不足以保留白色科技风的层次与角色辨识，可扩色并同步记录实际色板及受影响素材，不以旧色板限制已确认风格。半透明合成色与基础色板数量分别记录。
- 通过每组 `frameAnchor` 对齐同一世界脚底基线。**不能把所有帧硬设为 (16,47)**：个别组使用 (16,48)、(18,47) 或 (18,48)。以包内 `characters.json` 为唯一数据源。
- 角色与小动作预览按 8 fps 保存，图册允许临时调速检查；这不是游戏移动速度、整体帧率或业务等待时间。游戏倍率仍遵循 `map_rules.yaml`，图册更高整数倍率只用于看像素。
- VFX 单元为 16×16，固定显示／发射锚点 (8,15)。它们不定义天气规则或新增交互。

新增四向坐姿分别核验方向、椅面承托和定位锚点；8 帧性格动作要能被走动或搭话打断。职责附近的自主走动必须在预览中实际可见，核对整条路径、站坐切换和回位，不用一张坐姿图代替演示，也不把预写反应演成模型输出。

## 地图与 UI

办公楼改为老板室、9 工位开发区、洽谈室、卫生间、HR、行政前台及公共休憩节点。三名业务员工都在 dev；普通职员分别在 hr、admin、reception 附近。房间不按四象限等分，来访动线不穿过开发桌组；书架、鱼缸、绿植和中文部门牌不占门洞与主通道。歪绿植仍在开发部，桌面小物保留承托关系。咖啡店沿用既有前后台、座位与入口。

office 的九区为 `boss_office/dev/meeting/restroom/hr/admin/reception/commons/corridor`：老板室在西北，HR 在北中，卫生间从东北侧路进入；开发区在西中，洽谈室在东侧，公共区在西南、行政在南中、前台在东南。偏东主通路与横向支路连接各区，`office_to_street` 属于 reception。

开发席 `dev_01..dev_09` 的前三席分别绑定 example、closedoff、blog，其余六席为空。`hr_01/hr_02/admin_01/reception_01` 分别绑定四名正式职员；普通职员的岗位放在 `roster[].workplace`，不加入只含五名核心角色的 posts，也不进入 staff 派单表。

当前地图结构为 `office ↔ street ↔ cafe`。street 是无所属建筑的室外空间；办公楼与咖啡店各接街道，没有 office—cafe 直连。街道采用现代商业风，以写字楼、商场与连续商铺表现繁荣市区；6 处背景摆位在地图边界有意裁切，表示城市仍向外延续。除 office、cafe 外均只作场景陈设，不设可进入室内、交通或经济功能。新四名正式职员属于本次办公楼翻新范围。

可见顺序为 `ground → decoration → furniture → overhead`，另有隐藏的 `collision`。地毯、日光和接触阴影位于家具下；承托物、贴图锚点、地面排序点与碰撞格分别记录。作者数据见 `maps/*.layout.json`，编辑源见 `maps/*.tmj` 与 `world.tsj`。后续构建将其转换为运行时 JSON，不在游戏里解析 TMJ。

两组连接的各端都须保留独立的触发、到达与退回安全格；办公楼改图后重新核验入口与静态通路。街道既有基线为 547 个可走格、4 条 2 格净宽主通路。咖啡岗位示例保留原 15 格职责域，新职员使用新办公楼中各自明确的有限活动域；预览须显示实际走动且整条路径在域内。探险示例仍许可三图，业务员工仍在 office。完整游戏的跨图加载、返程、防连跳与恢复另验，机制连接尚未启用。

UI 区分派活、补充、回复指定员工、收尾、完成、待外部处理、部分完成、失败、取消与通道不可用。三名业务员工名牌使用“特殊NPC（业务员工）”，普通职员预写对白不提供模型输入、不挪用 staff 的执行入口。未来模型对白样张仍须标注接入前提。没有游戏内博客采用／发布确认按钮，完整材料不挤进气泡。

## 编辑与扩展

用 Pixelorama 打开交付包 `source/` 下对应 `.pxo`，选择时间轴标签查看或修改；街道环境工程有 20 帧、288×288 编辑单元，4 列导出，素材只补透明留白。用 Tiled 打开 `maps/office.tmj`、`maps/street.tmj` 或 `maps/cafe.tmj`，按三图一起检查相对素材引用与入口。角色帧、色板和锚点修改后，重新检查各向身份、道具、透明边、脚点及循环，再核验源文件导出。

新增建筑先确定用途、入口、区域与陈设；新增 NPC 先独立写性格与声音，再选择岗位型或探险型。沿用色板、视角、格子和脚点规范；不要把“咖啡店”推导成购买功能，也不要把探险的活动许可变成任意传送或业务权限。
