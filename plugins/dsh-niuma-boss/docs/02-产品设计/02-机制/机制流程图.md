# 机制流程图

这些图说明主要分支，不替代 YAML 的状态与条件。规则正文分别在 [任务协议](./task_protocol.yaml)、[角色状态机](./agent_fsm.yaml)、[地图规则](./map_rules.yaml)、[NPC规则](./npc_rules.yaml)与[交互规则](./interaction_rules.yaml)。

## 世界与地图

```mermaid
flowchart LR
    O[办公楼 office] <-->|office_street 双向连接| S[室外商业街 street]
    S <-->|cafe_street 双向连接| C[咖啡店 cafe]
    O --- B[开发部3位特殊NPC仍是staff；大总管靠老板室]
    O --- R[HR2人、行政1人、前台1人：普通职员职责域自主预览]
    C --- L[岗位 NPC：附近区域内活动]
    X[探险 NPC：无固定出生地] -.许可入口.-> O
    X -.许可入口.-> S
    X -.许可入口.-> C
```

办公楼与咖啡店没有直连，必须经室外商业街往返。街道无所属建筑，其余商业立面只作陈设；道路表现不增加交通玩法。两条连接仍为未启用的设计数据，须完成各自两端入口、到达格与返程验证后才能启用。老板可跨图；在外图时常驻牛马大总管入口仍然可用。三位特殊NPC不为追随老板跨图，无法到老板身边时说明位置限制，真实任务继续。新增4位普通职员只做预写对白、坐姿和职责附近可见活动，不进入staff或子任务流程。

```mermaid
stateDiagram-v2
    [*] --> stable
    stable --> loading: 选择已启用的合法入口
    loading --> stable: 目标校验成功，提交新地图与位置
    loading --> stable: 失败或取消，保留原图最后合法位置
```

加载过程中不再触发第二次切图，不新建、不暂停业务任务，也不把迟到的NPC回复显示到另一个人的对话里。

## 牛马大总管派活与顺序协作

```mermaid
flowchart TD
    Input[老板经牛马大总管发话] --> Plan[理解当前目标和输入版本]
    Plan --> Ready{前置条件满足吗}
    Ready -->|前一步尚在进行| Planned[留在 planned，不占员工]
    Planned -->|依赖变化| Plan
    Ready -->|无法恢复或材料缺失| Unmet[记录未完成原因，不伪执行]
    Ready -->|满足且有授权和容量| Dispatch[牛马大总管指定执行者，锁定归属]
    Dispatch --> Run[真实执行，动画同时推进]
    Run --> Result{返回结果}
    Result -->|成功| Data[保存真实结果与来源]
    Result -->|外部待办| External[保留材料和外部未完成事项]
    Result -->|失败| Retry{允许安全重试吗}
    Retry -->|是| Attempt[同一逻辑目标建立新尝试，保留旧失败]
    Attempt --> Plan
    Retry -->|否| Unmet
    Data --> PlanNext[检查尚待执行的依赖步骤]
    External --> PlanNext
    PlanNext -->|还有步骤| Plan
    PlanNext -->|无可推进步骤| EndGuard{所有子任务终结、最新输入已处理、当前目标逐项有结论吗}
    EndGuard -->|是| Summary[按当前有效目标结果汇总]
    EndGuard -->|否，继续处理输入或等待执行| Plan
    Unmet --> PlanNext
```

只有下游需要的真实材料齐全，且不依赖尚未发生的采用或发布，外部待办材料才可用于后续步骤。失败重试成功后可以完成原目标；失败历史仍保留，不把每次失败都永远累计成“部分完成”。额度不足时明示未完成目标。

## 老板补充要求

```mermaid
flowchart TD
    S[接受补充，递增 acceptedVersion] --> Understand[牛马大总管理解变更]
    Understand --> Kind{只改表达还是改变范围}
    Kind -->|只改表达| Reuse[复用仍适用的真实结果]
    Kind -->|范围或目标变化| Check[检查旧结果与下游依赖是否仍适用]
    Check -->|适用| Reuse
    Check -->|不适用| Replace[保留旧记录，停止旧尝试并建立替代或未完成项]
    Replace --> More[必要时重新派单，隔离未证明停止的执行]
    Reuse --> Version[更新 processedVersion]
    More --> Version
    Version --> Guard{版本一致且所有目标有结论吗}
    Guard -->|否| Understand
    Guard -->|是| End[原子提交本轮结果]
```

新输入与终态提交须原子判定。带着旧任务ID的草稿不能自动变成新任务；取消和超时收尾须保存未处理输入并明确未执行。

## 两个牛马大总管入口与 NPC 交流

```mermaid
flowchart LR
    Near[走近牛马大总管] --> Common[同一输入判定]
    Panel[任意地图常驻入口] --> Common
    Common --> Stop[收尾：禁用提交，保留草稿]
    Common --> Reply[员工等回复：选择具体问题，绑定子任务]
    Common --> Supplement[普通补充或牛马大总管追问：沿用当前任务]
    Common --> New[无活动任务：新建任务]
    NPC[走近当前地图 NPC] --> Talk[按该 NPC 的对白通道交谈]
    Talk --> Bound[不派员工任务，不调用未声明业务能力]
```

普通NPC对白不等于员工业务Agent接入。角色不在当前地图、通道不可用或正在切图时，不打开就近输入；常驻牛马大总管入口继续依照任务状态工作。
