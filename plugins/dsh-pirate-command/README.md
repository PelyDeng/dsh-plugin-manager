# 黑珍珠号指挥台

这个插件提供一个统一对话入口：杰克负责理解要求、安排工作和整合结果，巴博萨连接封闭化 Agent，伊丽莎白连接博客 Agent。业务查询、文章候选和操作确认仍由原插件处理。主入口不包含这两个业务插件的源码。

项目说明、已确定要求与协作规则统一见插件根目录 [AGENTS.md](AGENTS.md)。本文件只说明当前使用方式与接入接口；美术制作从 [资源入口](resources/README.md) 开始。

本插件是个人外部插件，源码与制作资料在私有 Gitee 集成库维护，适用本插件的 [LICENSE](LICENSE)；第三方依赖和改编的公共代码保留各自许可。公共框架仓库只提供通用 kit 和管理能力。构建及开发命令在私有库或本插件目录执行，仓库边界以 AGENTS 为准。

入口为 `/pirate`，健康检查为 `/pirate/ready`。同一官方 `dsh` profile 中启用入口和所需业务插件后，入口通过 Cordis 事件发现船员；插件未启用或用户无权访问时，页面显示岗位不可用。

## 使用

向船长描述目标、范围和产出要求。相关数据查询返回后，船长才能把必要摘要交给博客；互不依赖的任务可以同时处理。点击船员可切换交谈对象，右侧面板保留完整协作记录和原插件成果链接。

统计结果按实际查询的时间、页面或样本范围解读。一页返回较少记录不能单独证明已查完；缺少状态或总数等字段时，摘要和后续分析应保留“无法确认”的限制。

博客返回本轮仍待采用的实际候选标题和正文，供船长核对上游依据；发现问题后可交回伊丽莎白修改候选。过长内容未能完整转交时会明确说明，不能把这次核对当作全文审核。核对和修改不会替你采用或发布文章。

执行中可以补充要求。入口先显示“已接收”，宿主把消息纳入下一处理步骤后显示“开始处理”；这不代表正在运行的业务操作已经撤销或新的要求已经生效。具体调整以随后分工和结果为准。

停止会先进入“正在停止”，等待正在执行的工作结束后再收尾。停止不会撤销已保存内容。超时使用同样的收尾机制，不能把尚未结束的业务工作显示为已停止。

打开历史、刷新和断线重连只读取记录，不重新派单。服务器重启将未结束协作标为中断，需要用户明确继续。确认或采用博客候选应打开成果链接，在博客原页面完成；入口不取得确认凭据，也不替用户点击确认。

新协作发送后，如果入口暂时返回空体或非 JSON 的 404，页面会保留原内容和待确认请求，并清空模型目录。此时按输入区指引先点“刷新模型目录”，再按原内容重试，无须重新选择模型；刷新本身不会重新发送指令。登录失效或无权访问仍按原拒权提示处理。

本轮结束、候选稿生成、正文保存和文章发布是不同结果。未处理的船员失败或确认状态会保留；只问进度不会将等待确认改成已完成。

左下罗盘可打开船长输入。待命时合盖，进入任务或打开输入时开盖；指针表示公开协作阶段，只有本轮完成才对齐顶部 X。整轮失败会短暂乱转后显示裂盘与断针，等待、部分完成和停止保持完整。开启“减少动态”或读取历史时直接显示对应静态状态。

前帆显示船长已发布的当前公开主题，最多 3 个关键词，每词最多 8 个 Unicode 字符；尚未发布时留空。收到补充要求不会立即把帆面改成新消息，实际开始处理并更新主题后才变化。新一轮清除旧主题，停止和历史分页加载期间隐藏。

船首美人鱼木雕的绿色眼光只反馈整轮完成：实时完成短闪后保留弱光，历史或减少动态直接显示弱光。它不代表博客已发布或原插件确认已完成。声音默认关闭，可自行开启；当前合成提示与尚待交付的完整配乐分别记录在[资源清单](resources/资源清单.md)。

## 配置和构建

使用框架既有的插件安装和配置流程。包名为 `dsh-pirate-command`，插件 ID 为 `pirate`，配置入口为 `pirate-command`，默认不启用。通过 `/pirate` 访问需要 `pirate` 授权，调用船员还需要原插件授权。

当前依赖官方宿主 SDK `0.1.5-alpha.2`，使用 Session V3 的会话读取与投影接口。安装和构建前应对齐宿主及插件依赖；旧 SDK 或旧 kit 构建产物上的测试结果不能作为当前版本的接入验收。

本项目使用框架 `dsh-auth` 登录和授权，以 `authenticated` 模式接入。模型目录与 auth 的模型管理页面来自同一个官方宿主服务；普通用户无须调用 auth 的管理员接口。当前框架没有独立的每用户模型白名单。

输入区的“船长模型”控制主 Agent：未选择时，新协作继承官方默认模型，已有协作恢复自己的模型。选择具体模型或“使用 Auth 默认”后，在发送下一条消息时生效；运行中不能切换，但可以继续补充要求。官方接口在切换会话模型后尝试保存为宿主默认，保存成功才影响后续新会话；保存失败时，当前会话已切换，默认值仍可能保持原值。失效的模型会报错，需要明确选择有效模型，不静默回退。

博客和封闭化继续使用各自原会话的模型、工具、配置和用户数据；新的子会话继承当时的官方默认。指挥台不将船长的选择强行写入已有子会话，不另外保存模型凭据。

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `accessMode` | `authenticated` | 本项目使用统一身份；保留的 `standalone` 兼容模式不作为本次 auth 接入验收 |
| `publicOrigin` | 空 | 认证模式必须填写完整 HTTP(S) origin；写请求须来自该 origin |
| `routePrefix` | `/pirate` | HTTP 入口和资源前缀 |
| `historyPath` | 空 | 空值使用 `DSH_HOME/plugins/pirate` 内的历史库 |
| `turnTimeoutMs` | `600000` | 一轮协作的超时上限 |
| `authRecheckMs` | `1000` | 后台执行时复核原登录会话和业务权限 |
| `maxActiveMissions` | `16` | 本插件实例同时执行的协作数 |
| `maxMessageChars` | `8000` | 单条输入上限 |

在仓库根目录按需构建：`pnpm build --plugins pirate`。定向检查：`pnpm --filter dsh-pirate-command typecheck` 和 `pnpm --filter dsh-pirate-command test`。测试中的 HTTP、存储和派单是真实插件逻辑，模型与业务服务使用替身，不能将这些结果视为真实业务或浏览器验收。

一个历史库只由一个官方 profile 中的插件实例使用。不同实例配置独立历史路径，不共用 SQLite 文件；不在插件之外启动第二个业务服务。

## 业务插件接入

类型接口导出自 `dsh-pirate-command/protocol`。业务插件通过 `import type` 引用接口，并注册全局 `pirate/participants` 事件。海盗包作为可选 peer 和开发依赖，类型在构建后消除；没有安装指挥台时，业务插件继续独立运行。

参与者实现 `assertAccess(actor)` 和 `run(request)`，使用服务端传入的原始身份、自己的会话和工具权限。`run()` 接受停止信号，实际工作收尾后才返回。它可以通过 `onProgress` 提供简短状态，并尽早返回自己的 `conversationId`。

进度还有两种边收边显示的呈现数据：`kind: 'delta'` 带面向用户的正文增量，`kind: 'thinking'` 带已脱敏的可展示思考快照（完整覆盖，不是增量）。两者都不是协作事件，指挥台只把它们当作线索，不写入事件流、不落盘，参与者也只发送面向用户的正文与按自己口径脱敏的思考，不发送原始推理增量。

原插件核验会话归属后，可在同一条进度里附带 `conversationArtifact: { kind: 'conversation', title, path }`。指挥台检查当前运行、原插件权限和本站路径后保存入口，用户可在处理中打开，停止、失败或刷新后仍能回看。入口本身不表示业务完成；同次派单的重复会话链接只显示一次，同路径的候选稿或确认入口仍保留。协议版本仍为 1，未提供这个可选字段的旧参与者可以继续工作，但无法提前展示会话链接。

当前通过同一宿主内的 `Actor` 传递用户和登录会话标识，原插件重新核验权限。参与者协议不接收浏览器 Cookie、CSRF、模型密钥或业务 token；封闭化业务凭据由原插件按该用户身份读取，博客站点凭据由博客插件管理。

终态为 `completed`、`waiting`、`cancelled` 或 `failed`。只返回可见回答、会话标识和相对路径的成果链接，不返回内部推理、凭据或确认 token。业务插件负责保持未解决确认的 `waiting` 状态；入口负责保留未被后续结果解除的状态。

成功结果排除宿主重试时废弃的回答。失败或取消后若保留已有公开内容，必须同时明确本轮未完成；已有候选或待确认操作不能将失败、取消改为成功。

现有事件协议只在同一宿主进程内发现参与者，不能直接连接另一台服务器上的插件。跨进程部署需要单独的远程身份和通信设计。

## 模型接口

`GET /pirate/models` 返回官方目录 `groups`、暂时不可用的供应商 `failures`、当前默认 `default` 和当前协作模型 `selected`；新协作的 `selected` 为 `null`。带 `missionId` 时先核验协作及原业务插件权限，再恢复该协作模型。响应只含模型标识和名称，不包含配置或凭据。

模型目录读取返回 401、403 或 404 时，页面立即清除当前协作、历史和岗位可用信息；旧任务或旧访问范围的迟到回包不会清除新任务。503 等普通服务错误保留已读内容。拒权后不自动反复刷新模型目录，用户仍可显式刷新；宿主启动期的非 JSON 或空体 404 只沿既有任务 GET 路径有限恢复，不重新发送业务指令。

错误显示在当前详情或短输入内；收起后仍可从错误上方打开协作详情。长错误和短横屏面板可滚动读取，不遮住模型刷新、输入和底部场景控制。

`POST /pirate/message` 可以附带 `modelSelection`：省略表示继承，`null` 表示发送时的 Auth 默认，`{ "provider": "供应商标识", "model": "模型标识" }` 表示显式选择。模型必须在目录中且能通过官方路由校验。同一 `requestId` 必须保持消息、交谈对象和模型选择一致；不确定上次是否成功时重试原请求，不能更换模型后复用原请求号。
