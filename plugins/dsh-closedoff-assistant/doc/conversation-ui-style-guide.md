# 对话页面 UI 设计规范

## Summary

本文定义封闭化管理智能助手当前对话页面的视觉语言、信息层级、交互状态和复用规则，供其他业务模块设计同类智能对话页面时参考。

规范的核心目标是让一次对话按“思考过程、工具执行、结构化资料、模型分析”四个层次稳定呈现。无论模型调用一个工具还是多个工具，页面都应保持相同的信息顺序、状态语义和视觉结构。

本文描述当前实现，不要求其他模块复制封闭化业务名称。车辆、名单、轨迹等名称应替换为目标模块自己的业务分组，但交互模式和组件规则可以复用。

实现参考：[web/index.html](../web/index.html)。

## 设计原则

### 信息分层

页面把一次智能回答拆成四个互不遮挡的层次：

1. **思考**：说明模型当前正在处理什么，默认收起，仅预览最新进展。
2. **工具调用**：说明系统调用了哪些数据源、耗时多久、是否得到数据。
3. **结构化资料**：把工具返回的事实按业务类型聚合成统一卡片。
4. **模型分析**：对事实进行归纳、关联、风险识别和建议输出。

这四层必须保持顺序稳定。思考折叠时不能隐藏工具调用，工具调用完成后也不能与最终分析混为一块。

### 事实与分析分离

- 卡片负责展示可追溯的原始事实和关键指标。
- 模型文字负责解释事实、建立关联、指出异常并提出建议。
- 已在卡片中展示的数据，不再由模型生成一份重复表格。
- 模型不得把“未查询到记录”自动解释为“不存在”或“正常”。

### 通用框架与业务特例分离

思考、工具状态、卡片容器、分析区和异常状态属于通用对话框架。三维轨迹、摄像头查看等属于业务扩展槽，不应写死在通用组件内。

### 状态必须可理解

状态不能只依赖颜色。每个过程状态都应同时包含图标、文字和必要的数量或耗时信息。

## 视觉基础

### 色彩

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 页面背景 | `#f4f6fc` | 浅灰蓝，降低长对话阅读疲劳 |
| 次级背景 | `#f7f9fd` | 指标块、弱层级区域 |
| 主面板 | `#ffffff` | 消息、卡片和输入区域 |
| 强调浅底 | `#eef4ff` | 表头、代码和选中状态 |
| 分隔线 | `#e3e8f3` | 卡片边界和区域分隔 |
| 主文字 | `#2b3445` | 标题和关键内容 |
| 次文字 | `#5e6b7e` | 说明、时间和字段名 |
| 主色 | `#2457d6` | 图标、操作和流式光标 |
| 次主色 | `#2f6fe4` | 渐变和悬停状态 |
| 成功 | `#147a52` | 已完成、有数据 |
| 警告 | `#9a5700` | 调用中、范围提示 |
| 错误 | `#c83442` | 调用失败、回答失败 |

颜色是语义辅助，不替代文字标签。

### 字体

字体栈：`PingFang SC`、`Microsoft YaHei`、`Segoe UI`、系统无衬线字体。

- 页面标题：17px，字重 700。
- 助手正文：14px，行高约 1.75。
- 区域标题：13px 至 14px，字重 650 至 750。
- 辅助信息：11px 至 12.5px。
- 指标数字：18px，字重 750，使用等宽数字排版。

### 圆角和阴影

- 基础圆角：12px。
- 结果区域：10px。
- 数据卡片：8px。
- 标签和工具状态：8px。
- 阴影保持轻量，仅用于区分白色面板与浅色背景，不制造悬浮过强的视觉效果。

### 图标

图标统一采用 14px 线性图标，颜色继承所在状态：

- 思考：使用 DSH 思考图标。
- 工具调用：使用 DSH API 图标。
- 数据来源：使用列表图标。
- 状态图标与文字同时显示，不单独用圆点表达完整语义。

## 页面骨架

页面由顶部栏、对话主区、可选右侧栏和底部输入区组成。

```text
┌──────────────────────── 顶部栏 ────────────────────────┐
│ 品牌与业务说明                         状态 / 新对话 / 清空 │
├─────────────────────────┬─────────────────────────────┤
│                         │                             │
│       对话主滚动区       │       快捷提问侧栏          │
│                         │                             │
├─────────────────────────┴─────────────────────────────┤
│                    固定输入区                         │
└───────────────────────────────────────────────────────┘
```

### 顶部栏

- 白色背景，底部分隔线和轻阴影。
- 左侧品牌标识为 34px 蓝色渐变方块，圆角 9px，内部使用单字标识。
- 品牌名称下方显示业务范围说明。
- 右侧显示智能体状态、新对话和清空操作。
- 状态使用圆点、文字和胶囊容器共同表达。

### 对话主区

- 只有消息区域负责纵向滚动，页面根节点不产生第二条滚动条。
- 内容最大宽度约 1180px，宽屏居中显示。
- 背景采用浅灰蓝，消息卡片采用白色。
- 输入区始终固定在对话区底部，不随消息内容继续向页面下方漂移。

### 消息样式

**用户消息**右对齐，使用蓝色渐变背景、白色文字和气泡圆角，右下角保留较小圆角以表达方向。

**助手消息**左对齐，使用白色面板、浅边框和轻阴影。助手消息宽度接近对话主区宽度，以容纳工具列表、卡片和分析内容。

## 单轮对话的信息结构

助手的一轮回答按以下固定顺序渲染：

```text
助手回答
├─ 思考区域                默认收起，流式预览最新进展
├─ 工具调用区域            始终独立可见
├─ 结构化资料区域          按业务类型聚合
├─ 结论与建议 / 模型分析   流式输出
├─ 中断或错误状态          仅在需要时出现
└─ 回答操作与回合元信息    完整回答结束后显示
```

即使工具组合发生变化，也不能改变该层级。某一层没有内容时应整体隐藏，而不是保留空白卡片。

## 思考区域

### 默认状态

- 默认收起，不占用大段垂直空间。
- 左侧显示 14px 思考图标和“思考”标题。
- 标题后使用弱分隔点连接预览文字。
- 预览只显示一行，超出部分使用省略号。
- 正在思考时持续更新为最新一条稳定、可读的进展摘要。

预览内容应是安全的过程摘要，例如“正在核对车辆基础信息与最近通行记录”，不直接展示原始推理令牌或长篇内部推演。

### 动态反馈

- 运行中使用低强度扫光或呼吸动画，表示思考仍在继续。
- 动画周期约 2.6 秒，避免快速闪烁。
- 用户系统启用“减少动态效果”时停止动画。
- 思考完成后保留最终预览，不再持续闪动。

### 展开状态

- 点击整行可展开或收起。
- 展开后隐藏单行预览，显示完整过程摘要。
- 详情区最大高度约 320px，内容超出时内部滚动。
- 使用浅灰蓝背景、左侧强调线和 12.5px 正文。
- 保留换行，不强制改写为表格或卡片。

### 与工具区域的关系

思考和工具调用是两个独立区域。收起思考只影响思考详情，不影响工具状态、工具卡片和结构化结果。

## 工具调用区域

### 区域结构

工具调用位于思考下方，以顶部分隔线与思考区区分：

- 左侧标题固定为“工具调用”。
- 右侧显示本轮汇总状态。
- 下方使用可换行的工具状态卡片。

汇总状态示例：

- `正在查询 4 个数据源`
- `正在汇总结论`
- `已完成 8 项查询：有数据 4、无记录 4、失败 0`
- `未调用业务查询`

### 工具状态卡片

每个工具使用一个紧凑卡片，内容顺序为：

```text
[API 图标] 工具名称  1.2s  已完成
```

卡片使用浅色背景、细边框和 8px 圆角。桌面端自动换行，窄屏下每张卡片独占一行。

| 状态 | 颜色 | 文案 | 动态效果 |
| --- | --- | --- | --- |
| 调用中 | 橙色 | 调用中 | 图标轻微脉冲 |
| 已完成且有数据 | 绿色 | 已完成 | 无 |
| 已完成但无记录 | 灰色 | 无记录 | 无 |
| 调用失败 | 红色 | 调用失败 | 无 |

“无记录”与“调用失败”必须分开。前者表示接口正常返回空结果，后者表示本次查询没有得到可信结果。

### 多工具组合

- 卡片按照实际调用顺序显示。
- 不为某个固定问题写死工具数量或工具排列。
- 同一工具重复调用时应保留可区分的状态或合并规则，不能静默覆盖仍在执行的调用。
- 工具名称来自统一配置，不在多个组件中重复维护显示文案。

## 结构化资料区域

### 聚合方式

工具结果不按调用时间散落展示，而是按业务类型聚合。封闭化模块当前采用以下分组：

- 车辆概览
- 授权与名单
- 通行记录
- 轨迹与设备
- 预约与运单
- 风险信息
- 园区设施
- 其他资料

其他模块应替换为自己的业务分类。例如生产模块可以改为“设备概览、运行状态、告警、工单、能耗”，但仍保留统一的分组容器和数据卡片。

### 分组容器

- 桌面端默认两列网格，间距约 10px。
- 重要信息可以横跨两列。
- 720px 以下改为单列。
- 分组标题使用浅色表头、13px 加粗文字。
- 分组内按数据来源继续划分，每个来源显示名称、数量、状态和必要的查询范围提示。

当一个分组中的所有查询都没有记录时，在分组标题后显示“· 无记录”，不让用户逐个打开空内容确认。

### 数据卡片

普通卡片采用自适应网格，单卡最小宽度约 210px：

- 标题 13px、字重 700，下方使用弱虚线分隔。
- 字段采用“标签在左、值在右”的紧凑布局。
- 标签使用次级文字色，值使用主文字色。
- 数字使用等宽数字排版。
- 状态值可使用绿色、红色、橙色或蓝色，但必须保留文字。

概览类卡片可以包含：

- 主标题，如车牌号、人员姓名或设备编号。
- 一行紧凑属性，如类型、状态、归属。
- 多个指标块，如通行次数、告警数、待办数。

### Schema 字段使用

返回字段 Schema 同时服务于模型理解和卡片渲染：

- 字段标题用于生成用户可读标签。
- 字段类型决定数字、时间、布尔值和枚举的格式。
- 枚举说明用于把代码转换为业务文案。
- 展示优先级决定概览字段、详情字段和可省略字段。
- 敏感字段必须在进入卡片前过滤或脱敏。
- 未知扩展字段不进入模型或通用详情区；只有 Schema 明确声明且通过脱敏规则的字段才可展示。

卡片不应机械展示 Schema 中的所有字段。优先展示能帮助用户识别对象、判断状态和完成当前任务的字段。

### 空数据与不可展示数据

统一使用以下状态文案：

- `正在查询…`
- `本次查询失败，可稍后重试`
- `本次查询未发现记录`
- `已返回数据，暂无适合卡片展示的字段`

禁止生成只有“记录”标题但没有任何字段的空卡片。该规则适用于全部工具，不仅适用于车辆查询。

## 模型分析区域

### 位置与标题

模型分析位于全部结构化资料之后，以顶部分隔线和“结论与建议”标题开始。这样用户先看到事实，再看到模型对事实的解释。

### 分析职责

模型输出应完成以下工作：

- 概括最重要的查询结果。
- 关联多个工具返回的信息。
- 指出时间、状态、授权、轨迹或数量上的异常。
- 清楚区分“已确认事实”“合理推测”和“需要进一步核验”。
- 给出与当前问题相关的下一步建议。
- 说明查询时间范围和数据覆盖限制。

数据量较多时不能只展示卡片而省略分析。查询多个工具后，模型至少应提供跨来源总结；单独查询轨迹时，也应保留行驶路线、驻留情况和管理提示等分析能力。

### 避免重复

- 卡片已完整展示的字段，不再复制为 Markdown 表格。
- 分析文字只引用支撑结论所需的关键值。
- 没有结构化卡片时，模型可以使用表格帮助阅读。
- 同一异常只在最合适的业务小节说明一次。

### 输出过程

- 思考预览、工具状态和结构化资料可以流式更新；模型最终正文在服务端完整缓冲并统一脱敏后一次发送，避免手机号、身份证号或媒体地址跨分片时漏脱敏。
- 等待最终正文时可使用 8px × 15px 的蓝色状态光标表示仍在生成，但不能展示尚未完成脱敏的正文分片。
- 自动滚动仅在用户已接近底部时生效。
- 用户主动向上滚动后暂停自动跟随，避免页面持续抢夺阅读位置。

### Markdown 样式

模型正文支持段落、标题、加粗、列表、引用、行内代码、代码块和表格：

- 段落间距紧凑，保持连续阅读感。
- 表格占满可用宽度，表头使用浅蓝背景。
- 代码块使用浅灰蓝背景和内部滚动。
- 引用块使用左侧强调线，不使用大面积高饱和背景。

## 回答操作与回合元信息

完整回答结束后，在正文下方显示与 DSH 对话页一致的紧凑操作行，顺序固定为：复制、好回答、差回答、从这里创建新对话、用量、用时、完成时间。

- 图标按钮使用 28px 圆形命中区和 15px 线性图标，默认无边框背景，悬停或键盘聚焦时显示浅灰底色。
- 复制成功后，复制图标短暂切换为对勾并在 1 秒后恢复。
- 好回答和差回答是互斥状态；再次点击当前状态可撤销。评价写入服务端持久反馈，不只保存在页面内存。
- 创建新对话从当前已完成回合分支，保留此前上下文，同时不修改原对话。
- 用量和用时采用图标加紧凑文字胶囊，点击后显示精确明细；再次点击、点击外部或按 `Esc` 关闭。
- 用量明细区分未缓存输入、缓存读取、缓存写入、输出和其中推理；只有服务端能够证明准确时才展示。
- 完成时间使用当地时间的 `HH:mm`，悬停可查看完整日期时间。
- 480px 以下隐藏胶囊文字，只保留图标和可访问名称，避免把操作行挤成多行。

中断或失败回合不显示会误导用户的操作和统计数据。已完成但没有最终助手消息的回合可以显示分支、用量、用时和完成时间，复制及赞/踩仍要求存在最终助手消息。历史恢复后，操作行必须恢复相同元信息和评价状态；反馈服务不可用时明确显示不可恢复状态，不伪装为“未评价”。

## 异常与中断状态

异常状态位于本轮回答最下方，与分析正文分离。

### 警告状态

用于用户主动停止、达到长度限制、部分数据未完成或会话中断：

- 浅黄色背景。
- 黄色边框。
- 深黄色文字。
- 明确说明已完成的资料是否保留，以及用户能否继续分析。

### 错误状态

用于请求失败或无法继续回答：

- 浅红色背景。
- 红色边框。
- 深红色文字。
- 使用 `role="alert"` 和及时播报。
- 不覆盖已经成功展示的工具结果。

推荐文案结构：`发生了什么 + 已保留什么 + 用户下一步可以做什么`。

## 特殊业务内容

### 轨迹与设备

轨迹属于业务扩展槽，不是通用结果卡片的硬编码组成。

回答正文自动生成静态三维场景截图，展示轨迹、设备组图例、点位数量、设备数量和时间范围。多个轨迹截图串行生成，任一时刻最多创建一个临时 Viewer，截图完成后立即释放；用户可点击“全屏查看”进入独立的可交互三维弹窗。

“截图并保存”只放在全屏三维弹窗中。可见瓦片准备完成前按钮保持禁用；用户手动触发后下载当前视角 PNG，弹窗 Viewer、视角和交互状态保持不变。

### 轨迹布局

- 桌面端左侧为轨迹场景，右侧为 250px 设备图例。
- 默认高度约 420px。
- 图例内容超出时内部滚动，标题保持可见。
- 900px 以下改为上下布局，轨迹区约 340px，图例区约 190px。
- 正文自动截图和弹窗手动截图都必须等待当前视角的可见三维瓦片完成渲染，不能导出缺失模型的画面。

### 全屏弹窗

- 半透明遮罩配合轻度模糊。
- 内容最大宽度约 1420px，圆角 16px。
- 明确划分标题栏、内容区和底部操作区。
- 支持 `Escape` 关闭、点击遮罩关闭和键盘焦点循环。
- 关闭后焦点回到触发按钮。

摄像头等其他沉浸式业务内容可以复用同一弹窗外壳，但各自维护内容区和操作。

## 输入区与快捷提问

### 输入区

- 固定在对话区底部，内容最大宽度与消息区一致。
- 文本框字号 14px，最大高度约 140px，超出后内部滚动。
- `Enter` 发送，`Shift + Enter` 换行。
- 发送按钮为 44px 蓝色渐变方形按钮。
- 生成过程中切换为红色停止按钮，动作含义清晰可见。
- 输入区不能在消息内容较短时继续向页面下方漂移，也不能造成页面根节点可滚动到大面积空白区域。

### 快捷提问侧栏

- 桌面端宽度约 262px。
- 按业务主题分组展示问题入口。
- 问题按钮使用低对比度浅色背景，避免与主操作竞争。
- 900px 以下隐藏侧栏，把空间优先留给对话内容。

## 响应式与无障碍

### 响应式断点

**900px 以下：**

- 隐藏快捷提问侧栏。
- 轨迹与设备列表改为上下布局。
- 弹窗内容减少边距并改为更紧凑布局。

**720px 以下：**

- 结构化结果统一为单列。

**600px 以下：**

- 顶部栏变为两行布局并隐藏副标题。
- 缩小消息区左右内边距。
- 助手卡片接近满宽。
- 工具状态卡片每行一个。
- 输入区缩小边距。
- 摄像头等双栏内容改为上下布局。

### 无障碍

- 思考与工具运行状态使用 `aria-live="polite"`。
- 关键错误使用 `role="alert"`。
- 所有图标按钮都有可读名称。
- 键盘焦点有清晰的 `focus-visible` 样式。
- 弹窗实现焦点约束并在关闭后恢复焦点。
- 状态不能只用颜色表达。
- 尊重系统的“减少动态效果”设置。

## 建议的组件拆分

其他模块实现时可以复用以下组件职责，但无需为了未来假设继续拆分：

| 组件 | 职责 |
| --- | --- |
| `ConversationShell` | 页面骨架、滚动区、侧栏和输入区 |
| `AssistantTurn` | 组织一轮回答的固定信息顺序 |
| `ReasoningPanel` | 折叠、预览、流式状态和详情 |
| `ToolProgressPanel` | 工具汇总和工具状态卡片 |
| `ResultGroup` | 一个业务分类的标题、来源和状态 |
| `DataCard` | Schema 驱动的字段和值展示 |
| `MetricCard` | 概览对象和关键指标 |
| `AnalysisPanel` | 模型 Markdown、流式光标和自动跟随 |
| `TurnNotice` | 中断、警告和错误状态 |
| `AnswerActions` | 复制、持久评价、会话分支和回合元信息详情 |
| `BusinessFeatureSlot` | 轨迹、摄像头等模块专用内容 |
| `FullscreenViewer` | 全屏内容外壳、焦点管理和通用操作 |

组件复用应围绕稳定职责。不要为尚未出现的业务类型提前建立复杂插件协议，也不要把工具名称、业务分组或字段标签写死在通用组件中。

## 验收清单

### 信息结构

- [ ] 思考、工具、资料和分析按固定顺序显示。
- [ ] 思考默认收起，并持续预览最新进展。
- [ ] 收起思考不会隐藏工具调用。
- [ ] 没有内容的区域整体隐藏，不保留空白占位。

### 工具与资料

- [ ] 任意工具组合都能使用同一套状态卡片。
- [ ] 调用中、已完成、无记录和失败可明确区分。
- [ ] 工具结果按业务类型聚合，而不是按返回顺序散落。
- [ ] Schema 字段经过标题、类型、枚举和展示优先级处理。
- [ ] 空数组、空对象和缺少可展示字段不会生成空“记录”卡片。

### 模型分析

- [ ] 多工具查询完成后仍会生成跨来源分析。
- [ ] 单工具查询保留该业务需要的专项分析。
- [ ] 卡片与模型表格不重复展示同一批数据。
- [ ] 结论区分事实、推测和待核验事项。
- [ ] 分析说明查询范围和数据限制。

### 交互与布局

- [ ] 用户上滚阅读时，流式输出不强制拉回底部。
- [ ] 页面根节点不会滚动到输入区下方的大面积空白。
- [ ] 窄屏下结果、工具和业务扩展内容正确改为单列。
- [ ] 全屏弹窗支持键盘关闭、焦点循环和焦点恢复。
- [ ] 轨迹正文自动生成静态三维场景截图，多条轨迹串行处理且截图后释放临时 Viewer。
- [ ] “截图并保存”只出现在全屏弹窗，下载后弹窗三维场景和视角保持不变。
- [ ] 完整回答显示操作栏，窄屏下统计文字收起但功能和可访问名称保留。
- [ ] 复制、评价、分支、用量和用时详情均可操作；评价刷新后仍可恢复。

### 状态与可访问性

- [ ] 所有颜色状态同时提供文字。
- [ ] 流式状态可被辅助技术感知。
- [ ] 错误状态会及时播报且不覆盖已有结果。
- [ ] 减少动态效果模式下不播放非必要动画。

## Further Exploration

- 将设计令牌提取为模块共享的 CSS 变量文件，前提是第二个对话模块已经确认复用需求。
- 为 Schema 增加明确的展示提示时，优先补充少量稳定字段，例如展示标题、优先级和敏感级别，不把完整 UI 布局塞进接口 Schema。
- 如果后续出现三种以上重复的业务扩展内容，再评估统一的扩展槽注册机制。
